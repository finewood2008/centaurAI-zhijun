# MindOS Docker 容器镜像部署指南

本文说明如何在 Linux Docker 主机运行 MindOS 容器。容器镜像包含 Python 3.11 运行时、已锁定的 Python 依赖、MindOS Web 构建产物和后端代码；用户数据与模型必须通过主机目录挂载，不能写入镜像层。

## 1. 适用范围与安全边界

- 目标平台：Linux x86_64 Docker Engine，Docker Compose v2。
- 当前 Compose 配置使用 `network_mode: host`，仅适用于 Linux Docker 主机，不支持 Docker Desktop 的隔离网络模式。
- 后端继续监听 `127.0.0.1:8618`。host network 让容器内的 loopback 与主机 loopback 一致，保持后端已有的 `require_loopback` 与 CSRF 安全约束；不得自行添加 `ports:` 或将后端改为 `0.0.0.0`。
- 默认入口：`http://127.0.0.1:8618/mindos/`。通过反向代理开放访问时，代理必须运行在同一主机并回源到该 loopback 地址；不要直接公开普通 `/api/*`。
- 镜像和容器不是源码加密机制。拥有主机 root、Docker 控制权限或镜像读取权限的人员仍能取得运行文件和内存。敏感代码只能部署到可信基础设施。

## 2. 前置条件

安装 Docker Engine 和 Compose v2，并确认：

```bash
docker --version
docker compose version
uname -m
```

建议主机至少具备 4 核 CPU、16 GB 内存、50 GB 可用磁盘；启用 CLIP、Whisper 或 Ollama 时建议 32 GB 内存。Docker 守护进程需要能够访问主机数据卷目录。

以下命令假定仓库或受控构建上下文位于 `/opt/mindos/source`，模型和可变数据位于 `/srv/mindos`。

## 3. 准备主机数据与模型目录

容器内进程使用 UID/GID `10001`（`mindos`）。创建目录并赋予该账户写入数据根的权限：

```bash
sudo install -d -m 0750 -o 10001 -g 10001 /srv/mindos/data
sudo install -d -m 0755 /srv/mindos/models-cache
sudo install -d -m 0755 /srv/mindos/models-cache-ms
sudo install -d -m 0755 /srv/mindos/whisper-models
```

必需 BGE 文本模型挂载到容器的 `backend/models_cache`。主机模型目录必须至少包含：

```text
/srv/mindos/models-cache/BAAI/bge-small-zh-v1.5/config.json
/srv/mindos/models-cache/BAAI/bge-small-zh-v1.5/model.safetensors
# 或 pytorch_model.bin
```

建议从已验证环境复制完整模型目录。在线准备时，也可复用已构建的镜像下载，主机无需安装 Python：

```bash
docker run --rm --user root --entrypoint hf \
  -v /srv/mindos/models-cache:/models \
  mindos:local download BAAI/bge-small-zh-v1.5 \
  --local-dir /models/BAAI/bge-small-zh-v1.5
sudo chmod -R a+rX /srv/mindos/models-cache
```

`models-cache-ms` 与 `whisper-models` 是可选模型挂载：不启用视觉检索或音视频转写时可保持为空目录。镜像按离线优先配置运行，不会在容器运行时自动下载模型。

## 4. 配置 Compose

在构建上下文中复制环境变量模板：

```bash
cd /opt/mindos/source
cp .env.example .env
```

编辑 `.env`，填写绝对路径：

```dotenv
MINDOS_DATA_ROOT=/srv/mindos/data
MINDOS_MODELS_ROOT=/srv/mindos/models-cache
MINDOS_MODELS_MS_ROOT=/srv/mindos/models-cache-ms
MINDOS_WHISPER_MODELS_ROOT=/srv/mindos/whisper-models
```

`.env` 含本机路径，不应提交到版本库。启动前核对 Compose 渲染结果，确认没有意外端口映射或错误的卷路径：

```bash
docker compose config
```

## 5. 构建与启动

首次部署在受控构建机生成镜像：

```bash
cd /opt/mindos/source
docker compose build --pull
docker compose up -d
docker compose ps
docker compose logs -f mindos
```

镜像构建使用多阶段 Dockerfile：Node 20 只用于构建 `frontend/mindos-web/dist`，最终镜像不包含 Node.js、Git、`node_modules`、测试、Git 历史或主机运行数据。Python 依赖来自 `backend/requirements-lock.txt`，运行时为 Python 3.11。

健康检查和页面验收：

```bash
curl --fail http://127.0.0.1:8618/api/health
curl --fail http://127.0.0.1:8618/mindos/ > /dev/null
docker inspect --format '{{.State.Health.Status}}' mindos
```

首次启动会在 `/srv/mindos/data` 创建 SQLite、ChromaDB、Wiki、监控目录和后台任务状态。不要同时启动第二个容器或本机后端访问同一个数据根。

## 6. 反向代理与可选 AI

如需从局域网或公网访问，使用同主机的 Caddy/Nginx 代理到 `http://127.0.0.1:8618`，并单独配置 TLS、认证、访问控制与受信任网络范围。后端不应直接绑定到公网接口。

Ollama 可运行在宿主机并监听 `127.0.0.1:11434`。由于本 Compose 使用 host network，容器可访问该地址。启动前验证：

```bash
curl --fail http://127.0.0.1:11434/api/tags
```

未安装 Ollama 不会阻断基础索引，但摘要、Wiki 整理、问答和关系三元组会降级或不可用。

## 7. 备份、升级与回滚

备份必须在停止容器后执行，且必须备份整个数据根，不能只复制 `chroma.sqlite3`：

```bash
cd /opt/mindos/source
docker compose stop mindos
sudo tar -C /srv/mindos -czf /srv/mindos-backup-$(date +%Y%m%d-%H%M%S).tar.gz data
docker compose start mindos
```

升级步骤：

```bash
cd /opt/mindos/source
docker compose pull          # 仅使用远程镜像时需要
docker compose build --pull  # 本地构建时使用
docker compose up -d
docker compose logs --tail=100 mindos
```

升级只替换镜像，`/srv/mindos/data` 与模型挂载目录必须保留。回滚时将 `image: mindos:local` 改为之前验证过的镜像标签或 digest，再执行 `docker compose up -d`。升级或回滚前均应完成备份。

## 8. 常见故障

| 现象 | 处理 |
|---|---|
| `docker compose config` 提示环境变量未设置 | 将 `.env.example` 复制为 `.env`，填写四个绝对路径。 |
| 容器启动提示数据根不可写 | 确认数据目录由 UID/GID `10001` 拥有，或调整宿主机目录 ACL 后重启。 |
| `/mindos/` 返回 503 | 查看 `docker compose logs mindos`；镜像必须包含构建成功的 `frontend/mindos-web/dist/index.html`。 |
| 后端提示文本模型加载失败 | 检查 BGE 模型是否在 `MINDOS_MODELS_ROOT/BAAI/bge-small-zh-v1.5/` 下，且包含配置和权重。 |
| 外部请求得到 403 | 这是 loopback 安全约束。不得通过 Docker `ports` 绕过；改由宿主机反向代理并按项目远程访问设计配置。 |
| 启动提示数据根被占用 | 停止共享该 `MINDOS_DATA_ROOT` 的另一个容器、后端或维护脚本；不要删除锁文件。 |

## 9. 上线验收清单

- [ ] `docker compose config` 使用预期的主机绝对路径，且没有 `ports:`。
- [ ] `docker compose ps` 显示服务运行且 health 为 `healthy`。
- [ ] `GET /api/health` 与 `/mindos/` 可用。
- [ ] 使用资料页面上传一份文本，索引完成后可搜索到。
- [ ] 重启容器后资料、Wiki 与索引仍可读取。
- [ ] 已完成一次停止容器后的完整数据根备份。
- [ ] 若启用音视频，已验证 `ffmpeg`、Whisper 模型和对应挂载目录。
- [ ] 若启用 AI，已验证宿主机 Ollama 与 `qwen3:1.7b`。
