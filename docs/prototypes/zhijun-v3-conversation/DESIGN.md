# 知君 V3 · 对话式操作系统

## 产品命题

知君不是通用聊天工具，也不是个人知识库。它是一套由对话推动、由可信对象承接的个人本体 Data Agent：知君在关键时刻发起一段克制的对话，用户在对话中记录、澄清、判断和复盘；每轮有效对话都会同步形成可追溯、可修改、必须经用户确认的长期对象。

核心循环是：

```text
经历与问题 → 对话澄清 → 实时对象 → 用户确认 → 长期议题 → 结果回访 → 复盘与成长
```

对话负责降低表达门槛；对象负责建立可信结构；确认负责守住用户的最终解释权。

## 信息架构

V3 只保留五个一级入口：

1. 今日知君：晨间对话时间线。知君每天最多主动提出三个议题，并说明触发原因。
2. 议题：按判断、人物、关系和成长组织持续线程，不采用单一无限聊天历史。
3. 本体：同时提供“本体全景”和“对话校准”。前者让用户读取知君目前如何理解自己，后者通过对话确认四层自我——事实观察、自我表达、理想方向、知君推测。
4. 成长：承接判断结果、周复盘、人生章程和行动实验。
5. 数据与边界：来源、出盒、Agent 权限、设备、导出与删除的直接控制界面。

“待确认”不是一级待办中心。知君在相关议题里提出待确认理解，本体中保留集中治理入口。

## 本体的双视图

本体不是一张静态关系图，也不应退化为一串待确认卡。V3 使用同一份可信对象提供两个互补界面：

```text
对话校准（写入、解释、修正） ↔ 本体全景（读取、关联、回看）
```

- 用户从一级导航进入「本体」时，默认看到本体全景；从今日知君或相关议题处理候选理解时，直接进入对话校准。
- 全景中心是“当前的我”，周围同时容纳人物、关系、角色、项目、原则和判断方法，使用户能一眼看到“知君目前如何理解我”。
- 年轮位置表达可信状态：实线内环是用户已确认的理解；点线表示需要重申；朱砂虚线边界外是知君推测，明确标注“尚未进入本体”。
- 四层筛选表达认识论来源：事实观察、自我表达、理想方向、知君推测。人物／项目／事件／原则是对象分类，不能和四层自我混为一谈。
- 点击节点会同步显示当前版本、形成时间、具体理解和盒内依据；“就此和知君校准”把同一对象带回对话，而不是新开一段无上下文聊天。
- 候选理解只有在用户明确确认后才从虚线边界移入确认环，并同步更新四层计数；修正后继续停留在候选层，拒绝后从全景移除。

这套关系坚持一句产品原则：**对话是本体的写入方式，全景可视化是本体的读取方式。**

## 交互原则

- 默认短回应：复述当前理解、说明真实状态、只提出一个关键问题。
- 详细分析按需展开，结构固定为观察、依据、其他解释、反问和可选行动。
- 不展示伪造思维链，只展示“正在盒内寻找相关经历”“找到三段依据”“等待你确认”等可验证阶段。
- 桌面端采用对话 65% 与对象卡 35% 的共同思考桌；移动端对象卡收进底部抽屉。
- 本体全景桌面端同样采用约 65% 年轮与 35% 节点详情；移动端不压缩桌面图，而把节点转为双列浏览，详情使用底部抽屉。
- 用户说话或输入后，对象卡实时标出新增字段与来源，但只有明确点击确认才改变对象状态。
- 删除、高敏感确认、Agent 授权和片段出盒必须通过带影响预览的明确按钮完成，不能由一句自然语言代替。
- 重要语音在提交前必须经过实时转写、可编辑文本和最终确认。

## 视觉系统

整体沿用 V2 的“私人书房、镜与印”语言，但让知君的存在集中于对话节奏和一枚抽象呼吸印记，而非人物头像。

### 色彩

| Token | Value | Usage |
| --- | --- | --- |
| `--bg` | `#F3EFE6` | 纸色环境 |
| `--surface` | `#FFFCF6` | 对话纸面与对象卡 |
| `--fg` | `#1D211F` | 墨色正文 |
| `--muted` | `#686B66` | 次级说明 |
| `--border` | `#D8D3C8` | 书页分隔线 |
| `--accent` | `#A6452E` | 朱砂确认、印记和关键动作 |

不引入额外主色。成功、提醒和隐私等级优先通过文字、边框样式和图标表达，而不是大面积彩色状态块。

### 字体与形态

- 标题与关键知君话语：宋体栈，形成书信与人格感。
- 功能正文：苹方及系统无衬线，保证密度与可读性。
- 时间、状态和证据编号：系统等宽字体。
- 圆角克制，主要容器 18–24px；按钮 10–12px。
- AI 印记由同心圆和“知”字组成，只做低幅度呼吸。`prefers-reduced-motion` 下完全停止。

## 核心状态对象

原型使用独立虚构状态，不连接公共 API：

- `TopicThread`：议题类型、标题、主动触发原因、状态、关联对象、更新时间。
- `DialogueMessage`：角色、消息类型、正文、依据、可展开分析、建议字段变更。
- `LiveObject`：判断、理解、复盘或章程对象的当前字段、确认状态与依据。
- `VoiceDraft`：空闲、录音、转写、编辑、已确认。
- `BoundaryPreview`：接收方、用途、必要片段、隐私等级、一次性授权状态。
- `OntologyNode`：对象类型、四层来源、可信状态、当前版本、依据与关联议题。

## 三条主链

### 判断链

晨间议题 → 回答不可逆边界 → 判断卡同步更新 → 展开三段依据 → 明确确认判断 → 设置 9 月 8 日回访 → 进入持续议题。

### 本体链

知君提出一项待确认理解 → 候选节点位于本体信任边界外 → 用户补充关系背景 → 四层本体卡标出变化 → 用户确认、修正或拒绝 → 只有确认内容进入本体内环 → 从对话回看它在全景中的位置。

### 复盘链

判断结果到期 → 知君发起复盘 → 展开观察与替代解释 → 用户补充结果 → 共同形成十四日行动实验 → 回到原长期议题。

## 响应式行为

- `≥ 1180px`：固定侧栏，工作区为对话与对象卡双栏。
- `768–1179px`：窄侧栏，双栏比例收紧，对象卡仍可见。
- `< 768px`：底部五项导航；对话占满画布；对象卡通过底部抽屉打开；对话输入固定在底部导航上方。
- `< 768px` 的本体全景：隐藏装饰连线与大年轮，保留中心自我、四层筛选和双列节点；节点详情以可关闭、可由 Escape 退出的底部抽屉呈现。
- 全部宽度不得出现横向滚动。对话和对象卡内部独立纵向滚动。

## 可访问性与真实性

- 所有主要操作均使用原生 `button`，带明确 `aria-label` 或可见文本。
- Tab 可遍历导航、消息动作、输入与确认按钮；焦点轮廓清晰。
- Escape 关闭模态框和移动端对象抽屉。
- 所有图标均配文字或无障碍名称；状态不依赖颜色单独表达。
- 页面注明“原型使用虚构示例”；不把目标态能力误写成已部署能力。
- 知君只陈述可验证阶段和来源数量，不输出隐藏推理过程。
