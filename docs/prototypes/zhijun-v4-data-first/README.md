# 知君 V4「先知后君：数据建档与判断复利」原型

这是独立于 V2、V3 和生产前端的高保真交互原型。它用虚构资料演示知君如何把零散数据治理为长期记忆，让本体建立在可追溯的记忆地基上；成长则从真实判断和后来发生的结果出发，通过对话把一次经历变成下一次可验证的做法。内观镜保留为用户主动选择的情境深挖工具，不是成长的前置条件。

V4 的完整循环是：

```text
原始资料 → 盒内处理 → 可回忆事实 → 候选长期记忆 → 用户治理
    → 长期记忆 → 个人本体
    → 记下当时 → 等结果回来 → 一起复盘 → 形成下一步 → 再次验证
                              ↘ 可选内观镜（只属于当前情境）
```

成熟产品使用五个一级入口：`今日知君／记忆／本体／成长／盒子`。其中记忆是本体的数据地基，并通过`持续议题`保存事情的连续上下文；成长只负责判断、结果、复盘和方法验证；盒子承接连接、通讯、同步、资料处理、权限、出盒和维护。

## 启动

在仓库根目录运行：

```bash
python3 -m http.server 8623 --bind 127.0.0.1 --directory docs/prototypes/zhijun-v4-data-first
```

然后打开 <http://127.0.0.1:8623/>。

推荐通过本地服务器访问，不要直接依赖 `file://` 运行交互。

## 建议体验顺序

### 1. 完成数据先行建档

1. 在首屏选择一个认识方向。
2. 点击`从一件真实资料开始`。
3. 选择原型提供的虚构示例资料，并标注作者关系。
4. 查看“原件已保存 → 正在读懂 → 可以使用”的盒内处理状态。
5. 回答知君提出的一个语境问题。
6. 打开第一条初步候选，核对资料依据、用户原话和不确定性。
7. 点击`这确实像我`，查看它先成为长期记忆、再支撑个人本体节点，并生成朱砂回执。

### 2. 验证对话先行的边界

1. 重置原型后选择`手边没有，先聊几分钟`。
2. 完成一轮访谈，确认此时结果只被称为“你的自我表达”。
3. 补充一份虚构资料。
4. 查看系统如何在资料和用户解释汇合后才提出有材料支持的理解。

### 3. 核对首页候选长期记忆

1. 完成建档后进入`今日知君`。
2. 查看知君如何把 2021 年复盘与最近合作条款连接为一条候选长期记忆。
3. 回答它是一条长期原则，还是只适用于当前情境。
4. 点击`查看依据并核对`，确认“资料可用不等于长期记忆成立”。
5. 明确确认后，查看长期记忆回执及其对本体节点的影响。

### 4. 浏览记忆治理工作台

进入`记忆`，依次查看四个页签：

- `记忆工作台`：治理概览、六步记忆链、AI 盒内工作流和当前候选。
- `长期记忆`：已确认记忆、版本、依据、适用范围和本体影响。
- `原始资料`：作者关系、盒内处理状态、记忆影响和删除影响预览。
- `持续议题`：保存判断、关系和经历的连续上下文；到期判断、真实结果、复盘和方法验证回到`成长`处理。

打开任一长期记忆的`查看链路`，确认可以沿以下路径反向追溯：

```text
本体节点 ← 长期记忆 ← 可回忆事实 ← 原始资料
```

### 5. 打通成长的三条点击链

进入`成长`后，导航副标题应为`把真实选择变成可靠的方法`，页面主标题应为`把一次真实经历，变成下一次更好的选择`。桌面端是对话与复盘卡双栏，移动端通过底部抽屉查看复盘卡。

#### 结果已到 → 完成复盘

1. 打开唯一主任务`COO 任命 · 30 天结果已回来`。
2. 查看为什么现在值得复盘、用了哪些虚构资料和当时原话、预计约 4 分钟，以及完成后会留下什么。
3. 回答知君当前唯一问题，确认右侧复盘卡只更新为草稿。
4. 点击`查看依据`，展开当时判断、预期结果、信心、章程版本和具体来源。
5. 确认事实结果，再查看知君带依据的观察、其他解释和一个反向问题。
6. 选择`准确／部分准确／改成我的说法／不适用`治理知君的理解。
7. 选择下一次做法，并形成一条由用户确认的复盘经验；此时还不创建回访。
8. 明确确认后保存结果与复盘，查看回执中的来源、章程版本、“尚未建立新回访”和“未自动进入长期本体”的说明。
9. 若要继续验证，再点击`把下一次做法设为新的验证`，逐问确认备选方案、理由、信心、预期信号和回访时间后创建新的判断。

在出现价值张力提示时，可以打开内观镜或直接跳过。打开后应能返回原复盘和原问题；无论是否使用内观，都能完成这条链。

#### 没有事项 → 建立待观察判断

1. 切换到没有成长事项的空状态。
2. 回答“最近有哪件事，你想在一段时间后回来检验自己的判断？”。
3. 从近期虚构资料选择一件事，或手动描述一件事。
4. 通过逐轮单问题对话形成背景、备选方案、当前选择、理由、信心、预期信号和回访时间。
5. 明确确认后创建判断，进入`正在验证`，确认页面只显示回访时间，不制造每日任务。

#### 已完成复盘 → 再次验证

1. 打开一条已完成复盘，查看`当时判断 → 真实结果 → 留下经验 → 下一次`。
2. 点击`将下一次做法设为新验证`。
3. 确认小范围做法、预期信号和回访时间。
4. 明确确认后创建新的待观察判断，并回到`正在验证`。

若没有选择继续跟踪，小范围尝试只保存为原复盘的`nextAction`，不会创建新的独立实验对象。

### 6. 查看本体的记忆地基与可选内观镜

1. 进入`本体`，首先查看本体节点由多少条已确认长期记忆和原始资料支撑。
2. 点击`查看记忆地基`，确认可以返回记忆工作台。
3. 打开一个具体决定、关系或经历节点。
4. 在看到触发资料和“这不是结论”的说明后，主动同意开始内观。
5. 依次探索：
   - 本我 · 我想要什么
   - 超我 · 我觉得自己应该怎样
   - 自我 · 我如何面对现实
6. 校准平等三瓣图，并选择`成为之向 · 我愿意亲自选择什么`。
7. 将结果保存为本次情境的内观记录，确认它不会自动改变成长复盘、人生章程或个人本体。

### 7. 验证长期升级的二次确认

1. 打开已保存的情境内观。
2. 点击`这也是长期的我`。
3. 查看新的本体候选及其来源。
4. 完成第二次确认，确认它进入“自我表达”或“理想方向”。

### 8. 查看盒子连接与管理

进入`盒子`，依次查看五个页签：

- `盒子概览`：演示设备、连接、记忆服务、同步、最近出盒和资料流动路径。
- `通讯与同步`：可信设备、手机分享的待同步详情与接收回执、新设备配对、连接范围和盒子状态查询。
- `资料处理`：盒内任务、失败重试和返回记忆工作台核对候选的入口。
- `权限与出盒`：本地／云端运行位置、接收方、实际问题、用途、必要片段、一次性授权、完整调用回执与 Agent 权限。
- `维护`：CentaurOS、存储、记忆服务重启、导出、备份恢复和来源影响。

所有盒子在线、通讯、设备、同步、处理、存储和维护状态都是虚构演示。原型不会发现、连接、读取或控制任何真实盒子。

## 重点验证

- 未导入资料时，知君不会假装理解用户，也不会解释潜意识或稳定人格。
- 仅有访谈回答时，只能形成用户自我表达。
- `今日知君／记忆／本体／成长／盒子`五个一级入口在桌面和移动端一致。
- 成长第一视口能直接回答“成长是什么、我现在做什么、做完得到什么”，并且每轮只有一个主要问题。
- 成长页保留`正在验证／等我复盘／成长记录／我的方向`四个入口，任何时候只有一件主要成长任务。
- 结果已到、没有事项、已完成复盘三条成长点击链都能走通。
- 右侧复盘卡实时更新的是草稿；未经用户明确确认，不保存真实结果、复盘、长期方法或新的待观察判断。
- 知君的观察同时提供具体依据、其他解释和反向问题，并允许用户治理为`准确／部分准确／改成我的说法／不适用`。
- 首页候选长期记忆能回到两个时间点的资料和用户原话，且必须由用户确认。
- 记忆页完整显示`原始资料 → 盒内处理 → 可回忆事实 → 候选长期记忆 → 用户治理 → 长期记忆 → 本体`。
- 记忆工作台包含四个页签，本体页显式展示记忆地基。
- 盒子页包含五个页签，所有状态明确标注为虚构示例或演示状态。
- `只适用于这件事`不会进入长期本体。
- 内观镜必须由用户主动同意，可以跳过并返回原复盘；三种声音没有高低和人格分数。
- 内观记录默认只属于当前情境，不自动改变复盘、人生章程或本体，也不分享给万象。
- `这也是长期的我`会产生新的候选和第二次确认。
- 删除来源前会展示对候选记忆、长期记忆、本体节点、成长解释和内观记录的影响；变化后标记`依据已变化，需要重新核对`。
- 配对、撤销设备、重启、删除、Agent 授权和出盒不能由一句对话直接完成。
- 数据口径准确：原件不出盒，但问题与完成任务所必需的上下文片段可能出盒；发送前预览，发送后留回执。
- 快捷按钮不会发送任何未展示的第一人称事实。
- 结果卡只有形成可核对内容后才出现。
- 成长中不出现成长分数、人格评分、签到、连续天数或道德化评价。

## 响应式与键盘检查

请至少在以下宽度检查原型：

- 1440px：完整桌面布局，成长显示 65% 对话与 35% 复盘卡。
- 1024px：窄侧栏，成长对话与复盘卡改为上下排布。
- 390px：单列建档与成长对话、底部导航、复盘卡底部抽屉和分步内观卡。

同时验证：

- 页面没有横向滚动。
- Tab 可以完成主要点击链，焦点轮廓始终可见。
- Escape 能关闭模态、结果侧卡和移动端抽屉，并恢复触发点焦点。
- 200% 缩放后主要内容仍可使用。
- `prefers-reduced-motion` 下呼吸和转场动画停止。
- 浏览器控制台没有错误。

## 能力与边界

### 现有底座可复用

- 文件类型和大小校验。
- 上传、排队、处理、完成、失败与重试状态。
- 文档解析、图片和扫描 PDF OCR、音频 ASR。
- 摘要、标签候选、实体与关系派生。
- 资料版本、本地检索与证据问答。

### 现有成长接口映射

本轮不修改公共 API，原型状态严格映射现有对象：

| 用户看到的内容 | 现有对象／状态 |
| --- | --- |
| 我的方向 | `GrowthCharter` |
| 正在验证／重要选择 | `GrowthDecision` |
| 真实结果 | `GrowthDecisionOutcome`（产品语义可简称 GrowthOutcome） |
| 成长复盘 | `GrowthReview` |
| 本周最值得处理的事 | `GrowthTodayItem` |
| 等结果／待复盘／已留下方法 | `open / outcome_recorded / reviewed` |

`我的方向`沿用章程历史响应里的`currentCharter`与`versions`，不另建方向模型。

不新增独立的 `ActionExperiment`。`小范围尝试`先保存为 `GrowthReview.nextAction`；只有用户选择继续跟踪并确认预期信号与回访时间时，才创建新的 `GrowthDecision`。

### V4 目标产品能力

- 资料作者关系和语境说明。
- 对话访谈作为独立来源。
- 可回忆事实、跨来源证据、候选长期记忆、用户治理和长期记忆。
- 个人本体、情境内观、成为之向和长期升级。
- 判断、真实结果、用户治理的复盘、下一步与再次验证的对话式产品编排。
- 盒子连接、通讯、同步、处理、权限、出盒和维护的目标产品交互。

其中证据展开、自动挑选唯一成长主任务、复盘卡实时草稿、稍后提醒和内观返回原复盘是高保真原型能力，不代表已有对应的服务端自动化或持久化能力。

### 本原型没有实现

- 不连接后端，不调用现有 API，不读取真实文件。
- 文件选择、处理、OCR、ASR、保存、删除和检索均为虚构交互。
- 不提供邮箱、微信、日历、Notion 或云盘等通用连接器。
- 不执行真实出盒、Agent 授权、设备配对、同步、系统维护或数据删除。
- 不扫描本地网络，不读取盒子状态，不控制真实硬件，也不发送重启或更新命令。
- 不实现从新资料到统一问答、长期记忆、个人本体、成长复盘和其他 Agent 的生产级贯通。
- 不提供心理诊断、人格评分或自动潜意识解释。

所有人物、资料、证据、记忆、判断、结果、复盘、内观记录、Agent、设备和盒子状态均为虚构示例。原件不被读取、上传或发送。

正式产品的数据口径是：原件保存在私人记忆盒子中，云上没有原件；调用云端模型时，问题与当前任务所必需的上下文片段可能出盒。发送前必须展示接收方、用途和精确片段并取得明确授权，发送后保留可检查回执。不能把“原件不出盒”表述成“任何数据都不出盒”。

## 哲学说明

本我、自我、超我来自弗洛伊德的结构模型；“成为之向”受尼采的价值重估、自我超越与“成为自己”启发。两者在产品中明确分开，只作为用户自愿使用的情境反思工具，不构成心理学测评、人格诊断或关于用户的事实，也不是完成成长复盘的必要步骤。

完整设计规范、状态模型、能力真实性表和验收标准见 [DESIGN.md](./DESIGN.md)。
