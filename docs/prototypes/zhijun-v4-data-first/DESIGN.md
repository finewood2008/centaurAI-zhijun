# 知君 V4 · 先知后君：数据建档与判断复利

## 产品命题

知君不是一位在没有依据时也能侃侃而谈的聊天机器人，而是一个由真实个人资料驱动、由用户最终解释的个人 Data Agent。

V4 把第一次价值体验从“立即获得建议”改为“建立第一条有来路、可核对的自我理解”：原始资料先在盒内变成可追溯事实，再由知君提出候选长期记忆；用户决定什么值得长期留下，本体只承接这些经过治理的记忆。对话补足当时的语境；成长则把一次真实判断、后来发生的结果和用户确认的解释连起来，让经验成为下一次可验证的做法。内观镜只在具体情境出现价值张力时提供可选深挖，不是成长的前置条件。

核心循环是：

```text
原始资料 → 盒内处理 → 可回忆事实 → 候选长期记忆 → 用户治理
    → 长期记忆 → 个人本体
    → 记下当时 → 等结果 → 一起复盘 → 形成下一步 → 再次验证
                              ↘ 可选内观镜（只属于当前情境）
```

V4 坚持四条底线：

1. **没有数据，不假装懂你。** 仅凭一次对话不能推断稳定人格，更不能解释“潜意识”。
2. **对话是资料的解释器，不是资料的替代品。** 用户原话、资料事实和知君推测始终分开。
3. **只有确认才能成为本体。** 候选、修正、拒绝与适用范围都由用户治理。
4. **哲学只是一面可选择的镜子。** 内观镜不做心理诊断、人格评分或道德排序，也不阻断判断复盘。
5. **经验由用户确认后才成立。** AI 不代填真实结果；未经用户确认，不保存结果、复盘或长期方法。
6. **盒子状态必须诚实。** 本原型中的在线、通讯、同步、处理、存储与维护状态全部是虚构演示，不代表已连接真实硬件。

## 首次体验：先建立认识，再开始陪伴

### 建档首屏

新用户默认进入独立建档模式，不出现成熟产品的复杂侧栏和任务工作台。

主文案：

> 先让我认识真实的你
> 知君不会凭空给建议，也不会只凭一次聊天定义你。先给我一点真实资料——你写过的、说过的、正在经历的。

信任承诺固定出现：

> 原件留在盒内 · 只有经过你确认的理解才会留下

用户先选择一个认识方向：

- 想清一个正在做的决定
- 理解我的做事方式
- 记住重要的人和关系
- 整理一段重要经历

选择方向只用于推荐资料和访谈问题，不产生人格标签。随后用户可以自由决定从哪条路径开始：

- `从一件真实资料开始`：推荐路径。
- `手边没有，先聊几分钟`：先形成用户自我表达，稍后补充资料。

两条路径最终汇合。首次建档不是用百分比推动的表单，而是三章式关系进展：

1. 给知君一份真实来路
2. 由你解释其中的语境
3. 一起核对第一条理解

用户可以暂停建档或先浏览产品。若尚未形成数据基线，所有个性化区域必须明确说明“知君还不够了解你”，不能生成虚构建议、主动人格解释或跨经历模式。

### 最小资料包

首次只邀请导入 1–3 份与所选方向最相关的材料，降低压力。优先推荐：

- 用户亲自写过或深度修改过的笔记、方案、文章、PPT、备忘录与复盘。
- 与当前决定、项目或困扰有关的一份真实材料。
- 简历、个人介绍或简单人生时间线。
- 一次过去判断及其最终结果。

关系和多人聊天资料属于高敏感来源，首次优先建议使用用户自己的记录；多人共同内容必须明确提示其中包含第三方信息。

每份资料导入后补充作者关系：

- 主要是我写的或说的
- 我深度参与过
- 他人为主
- 多人共同内容

作者关系用于约束后续解释，避免把他人的表达误认成用户本人的信念。

### 支持格式与限制

原型只展示底座真实白名单：

| 类别 | 格式 | 单文件上限 |
| --- | --- | --- |
| 文档 | PDF、DOCX、TXT、Markdown、XLSX、XLSM、XLS、PPTX | 50MB |
| 图片 | PNG、JPG、JPEG | 50MB |
| 音频 | MP3、WAV、M4A | 200MB |
| 轻量输入 | 粘贴文字、从手机分享 | 原型演示 |

不把邮箱、微信、日历、Notion 或云盘描述为当前已经可用的自动连接器。

### 盒内处理状态

处理过程不用“切片、向量化、实体抽取”等工程语言，也不展示虚构百分比。每份资料独立经历：

- 原件已安全保存
- 等待盒内处理
- 正在读懂内容
- 正在区分你的表达、他人的观点和材料事实
- 找到值得与你核对的线索
- 这份资料可以使用
- 处理失败，可重试或删除

单份资料失败不阻断其他资料。失败、损坏、加密、不支持或超限的材料不得进入候选理解。

## 对话式资料解释

处理资料时，知君同步通过每轮一个问题的短访谈补充语境。问题根据用户选择的方向和已导入资料生成，例如：

- 当时发生了什么？
- 这件事里你最在意什么？
- 哪个边界不能被交换？
- 哪段过去经历正在影响今天？
- 你希望知君以后如何提醒或挑战你？

每条回答明确标注为`你亲口告诉知君的建档资料`，允许编辑、删除、跳过和设置隐私范围。用户原话不得被知君的改写覆盖。

若用户先完成访谈而没有导入资料，系统只能形成“用户自我表达”，不能声称发现跨经历规律；知君随后邀请用户补充一份最相关材料。

## 第一条可信理解

只有同时满足以下条件，知君才提出第一条候选理解：

- 至少一份资料处理成功。
- 至少有一条用户访谈解释。
- 理解能够连接两个来源或两个明确时间点。
- 每条依据可以回到具体资料片段或用户原话。

候选理解固定展示：

- 我的初步理解
- 为什么这样理解
- 资料依据
- 用户原话
- 我还不确定什么
- 当前证据强度

证据强度只表达认识论状态，不给用户打分：

- 你的自我表达
- 有材料支持的初步理解
- 跨经历理解

用户可执行五种治理动作：

- `这确实像我`
- `部分准确`
- `只适用于这件事`
- `不对`
- `先别保存`

只有明确确认的内容才能先成为长期记忆，并进一步支撑个人本体。“只适用于这件事”只保存到相关议题，不升级为长期自我理解；拒绝内容不会进入长期记忆、本体、Agent 上下文或未来回答。

首次确认后生成“朱砂回执”，说明确认内容、长期记忆版本、使用来源、本体层次、允许用途、未提供给哪些 Agent，以及删除来源后的影响。第一条长期记忆成立后，才支撑确认节点从信任边界外进入本体内环，形成第一次“被理解”的可见成果。

## 成熟产品的五个入口

完成第一版建档后开放五个一级入口：

1. **今日知君**：第一视口只突出一条最值得核对的候选长期记忆，或一件到期的成长回访；其余盒内工作折叠展示。
2. **记忆**：知君的数据治理工作台，完整呈现资料如何经过盒内处理、事实形成、候选提出和用户治理，最终成为长期记忆。
3. **本体**：以个人本体可视化为主体，并显式展示支撑节点的长期记忆和原始资料地基。
4. **成长**：把真实选择变成可靠的方法；记录当时判断，等待结果，和用户一起复盘，再形成下一次可验证的做法。
5. **盒子**：呈现私人记忆盒子的连接、通讯、同步、资料处理、权限、出盒与维护；所有状态均为未连接真实硬件的虚构演示。

持续议题不再占用一级导航，而是进入`记忆 → 持续议题`，保存事情、关系与资料的连续上下文；`成长`只负责判断、结果、复盘和方法验证，避免两个板块重复。侧栏长期保留`添加资料`，并提供可点击的盒子状态入口，使资料摄取和硬件连接都不是一次性 onboarding。

持续循环为：

```text
新增资料 → 盒内处理 → 可回忆事实 → 候选长期记忆 → 用户核对
    → 长期记忆 → 支撑本体 → 支持成长与持续议题
```

## 记忆治理：本体的数据地基

### 记忆治理链

V4 必须持续呈现同一条因果链：

```text
原始资料 → 盒内处理 → 可回忆事实 → 候选长期记忆
    → 用户治理 → 长期记忆 → 本体
```

各阶段不能互相冒充：

- **原始资料**是用户交给盒子的文件、文字、图片或音频，原件与版本留在盒内。
- **盒内处理**负责读取、转写、区分作者和观点，并生成可定位的证据；处理完成不代表形成长期记忆。
- **可回忆事实**是能够回到具体来源的事件、原话、人物关系或材料事实，不等于对用户的稳定解释。
- **候选长期记忆**是知君建议长期保留的内容，必须显示依据、连接原因、不确定性和适用范围。
- **用户治理**包括确认、修正、限定为当前情境、拒绝和暂不保存。
- **长期记忆**只有在用户明确治理后成立，可以用于未来回忆，并在授权范围内支撑本体。
- **本体**只能建立在可追溯、经过治理的长期记忆上；没有记忆地基的 AI 推测留在信任边界外。

访谈回答作为`用户自我表达`补充候选记忆的语境，但不能替代原始资料和跨时间证据。

### 今日首页的候选记忆

今日首页首先让用户看见知君正在治理记忆，而不是直接给出脱离数据的判断。虚构示例中，知君说明昨晚处理了两份资料，展示它们连接的两个时间点，并只提出一个关键问题：这是一条长期原则，还是只适用于当前合作？

首页候选必须遵守：

- 第一视口只出现一条候选长期记忆和一个主动作`查看依据并核对`。
- 明确说明“资料可用不等于记忆成立”。
- 折叠展示仍在安静处理的资料任务，不制造待办压力。
- 用户确认后生成长期记忆回执，说明保存位置、依据、适用范围、本体影响和 Agent 范围。

### 记忆工作台的四个页签

1. **记忆工作台**：展示虚构治理概览、六步记忆链、AI 盒内工作流和当前最值得核对的候选。
2. **长期记忆**：展示已经由用户确认的记忆、版本、时间跨度、证据数量和本体影响，并支持查看完整链路。
3. **原始资料**：展示作者关系、盒内状态、记忆与本体影响，以及删除来源前的影响预览。
4. **持续议题**：保存正在发生的判断、关系和经历的连续上下文，使用户不必重复交代；到期判断、真实结果、复盘与方法验证统一回到`成长`处理。

来源删除或版本变化必须沿依赖链标记影响。长期记忆可以保留历史版本，但失去有效依据后必须进入`需要重新确认`，不能继续作为确定事实支撑本体。

## 盒子：连接、运行与边界

`盒子`是独立一级入口，不再埋在数据治理的末级设置中。它同时承担“我怎样和盒子通信”与“盒子怎样守住数据边界”两种任务。

### 五个盒子页签

1. **盒子概览**：展示演示设备身份、连接、记忆服务、同步与最近出盒状态，以及`手机／电脑 → 盒内保存 → 本地处理 → 云端模型`的数据路径。
2. **通讯与同步**：展示可信设备、待同步内容与接收回执、新设备配对流程、设备连接范围和与盒子的状态查询对话。配对、撤销、网络切换、重启和删除必须通过明确控制完成；同一网络只用于传输，不能作为设备可信依据。
3. **资料处理**：展示盒内处理、失败与重试状态；处理完成的候选仍返回记忆工作台由用户治理。
4. **权限与出盒**：展示本地／云端运行位置、接收方、实际问题、用途、精确必要片段、一次性授权与完整审计回执，并管理万象及其他 Agent 的读取范围。
5. **维护**：展示 CentaurOS、存储、记忆服务重启、导出、备份恢复和来源影响等预期流程。

数据出盒口径必须准确：

> 原件不出盒，云上没有原件；调用云端模型时，问题与完成当前任务所必需的上下文片段可能出盒。发送前必须展示接收方、用途和精确片段，并由用户明确授权，发送后留下回执。

不能把“原件不出盒”扩大成“任何数据都不出盒”。同样，界面中的盒子在线、最后通讯、设备、同步、任务、存储、系统版本、备份校验和重启结果全部是虚构交互状态；原型未发现、连接、读取或控制任何真实盒子。

## 本体：证据骨架与内观镜

### 四层本体

V4 保留 V3 的四层本体作为认识来源和治理骨架：

- **事实观察**：可回到具体资料、事件与时间点的观察。
- **自我表达**：用户亲口表达并确认的自我理解。
- **理想方向**：用户主动选择并愿意实践的价值与方向。
- **知君推测**：等待用户核对的 AI 候选，位于信任边界外。

四层不是人格类别，也不存在高低关系。对话是本体的写入与校准方式，本体可视化是读取、关联和回看的方式。

### 可见的记忆地基

本体页在图谱之前固定展示`本体的数据地基`：原始资料数量、已确认长期记忆数量、本体节点数量，以及需要重新核对的记忆。用户可从地基返回记忆工作台，也可以从任一本体节点反向查看：

```text
本体节点 ← 长期记忆 ← 可回忆事实 ← 原始资料
```

原型中的数量全部是虚构示例，不表达“人格完整度”或认识用户的百分比。没有长期记忆支撑的候选节点使用待确认状态，并停留在信任边界外。

### 可选视角：内观镜

`内观镜`不新增一级导航，也不替代四层本体。入口可以位于本体中的具体决定、关系、经历或重复模式内，也可以在成长复盘发现明确价值张力时出现。成长中的统一提示是：

> 想更深地理解这次拉扯？可以打开内观镜，也可以直接完成复盘。

只有用户明确同意，内观才开始；跳过后仍可完整完成成长闭环，返回时恢复原复盘位置。没有资料依据时，知君不得主动解释用户的本我、超我或潜意识。

### 哲学归属与生活语言

本我、自我、超我来自弗洛伊德的结构模型；尼采不属于这套三分结构。V4 将两者严格区分：

- **本我 · 我想要什么**：欲望、需要、渴望、害怕和不愿失去的东西。
- **超我 · 我觉得自己应该怎样**：责任、规范、身份要求，以及家庭、职业或社会留下的期待。
- **自我 · 我如何面对现实**：面对约束、代价和后果，用户准备如何选择与承担。
- **成为之向 · 我愿意亲自选择什么**：受尼采的价值重估、自我超越与“成为自己”启发，帮助用户区分继承来的价值和自己愿意实践的价值。

页面必须注明：

> 本我、自我、超我视角受弗洛伊德结构模型启发；“成为之向”受尼采自我超越思想启发。这是一种反思工具，不是心理诊断或人格结论。

三种声音使用平等三角或三瓣式视觉，不制作“本我低级、超我高级”的金字塔，不提供人格分数，不出现“本我过强、超我不足、控制型人格”等诊断语言。

### 内观流程

内观固定为一条可退出、可逐项修正的八步流程：

1. 展示触发内观的资料、事件和用户原话。
2. 询问用户是否愿意开始。
3. 探索本我：如果暂时不考虑身份、后果和他人看法，你真正想要什么？
4. 探索超我：你觉得自己应该怎样？这个“应该”更像来自你自己，还是他人留下的要求？
5. 探索自我：考虑现实代价后，你准备怎样行动并承担结果？
6. 展示平等三瓣内观图，由用户逐项修正。
7. 用户选择愿意认同并实践的“成为之向”。
8. 形成情境化内观记录并返回原情境；若从成长进入，则回到未完成的复盘，不自动改变复盘结论或下一步。

每一种内在声音都必须标明来自用户原话、资料观察还是知君推测，并允许分别选择：

- 准确
- 部分准确
- 只适用于本次
- 没有这种声音
- 改成我的说法
- 不保存

### 保存与长期升级

内观结果默认仅保存到当前决定、关系或经历，状态为`本次情境的内观记录`，不直接进入成长结论、人生章程、长期记忆或个人本体。

只有用户主动点击`这也是长期的我`，系统才创建新的本体候选，并要求第二次明确确认：

- 用户确认的自我理解进入“自我表达”。
- 用户选择长期实践的价值进入“理想方向”。
- AI 对动机的解释继续留在“知君推测”。

相似张力在多个情境中重复出现时，知君只能邀请用户核对，不能自动生成永久人格标签。内观记录默认最高敏感等级，不自动提供给万象或其他 Agent。内观与长期升级始终是旁路能力，不能成为记录真实结果或完成复盘的必经步骤。

## 成长：把真实选择变成可靠的方法

成长的核心价值是：

> 把一次真实经历，变成下一次更好的选择。

它不以“内观—成为之向—14 天实验”的抽象叙事开场，也不要求用户先接受一套哲学框架。主循环固定为：

```text
记下当时 → 等结果回来 → 一起复盘 → 形成下一步 → 再次验证
```

“成长”只处理判断、预期、真实结果、复盘和方法验证；“记忆／持续议题”保存事情的连续上下文与相关资料。人生章程保留为`我的方向`详情，不作为理解成长首屏的门槛。

### 首屏：只处理一件最值得复盘的事

一级导航仍叫`成长`，导航副标题为：

> 把真实选择变成可靠的方法

页面主标题为：

> 把一次真实经历，变成下一次更好的选择

桌面端使用“对话 65% + 复盘卡 35%”布局；移动端保持单列对话，复盘卡折叠为可关闭的底部抽屉。第一视口必须同时回答三件事：成长是什么、用户现在要回答什么、完成后会得到什么，但任何时刻只显示一个主要问题和一个主要动作。

默认虚构案例为`COO 任命 · 30 天结果已回来`。知君直接提问：

> 30 天前，你希望观察沈禾能否独立主持周会并处理冲突。现在四次周会已经结束，其中两次冲突仍由你收尾。先不急着评价她：这次结果里，最出乎你意料的是哪一件？

问题附近明确展示：

- **为什么现在值得复盘**：30 天回访时间已到，四次周会提供了可以核对的真实结果。
- **用了什么资料**：`COO 任命记录 · 30 天前`、`周会记录 · 第 1–4 周`，以及用户当时原话“我希望她能独立主持周会，冲突出现时不需要我再收尾”；每项可展开到具体来源。所有内容均标注为虚构示例。
- **需要多久**：预计约 4 分钟。
- **完成后留下什么**：真实结果、你的解释、至少一条复盘经验和下一次做法；是否继续验证与回访需另行确认。
- 次级动作：`换一件事`、`稍后提醒`、`查看依据`。

同一页面最多再折叠展示两件次要事项，不与主要任务竞争。AI 不能根据周会资料代填“实际发生了什么”；资料只能帮助定位事实，事实结果必须由用户确认。

右侧复盘卡随着回答实时更新，但确认前始终标记为`草稿，尚未保存`。卡片依次容纳：

- 当时怎么想：原判断、预期结果、信心，以及当时有效的章程版本。
- 实际发生了什么：只呈现用户确认的事实结果。
- 哪里最出乎意料：保留用户解释，并用`事实／你的观点`清楚分栏。
- 知君怎么看：有具体依据的观察、至少一种其他解释和一个反向问题。
- 这次留下什么：用户确认的`lessons[]`与`nextAction`；预期信号和回访时间只属于随后可选创建的新判断。

### 对话式复盘闭环

每轮默认只问一个关键问题，回答后只推进一层，并更新复盘卡草稿：

1. **当时怎么想**：回看原判断、预期结果、信心和当时绑定的章程版本；用户可以指出原记录不准确。
2. **实际发生了什么**：请用户确认可以观察到的结果，AI 不代填，也不把评价伪装成事实。
3. **哪里最出乎意料**：记录用户解释，明确区分事实和观点。
4. **知君怎么看**：展示带来源定位的观察、其他可能解释和一个反向问题；不得只给无依据结论。
5. **用户治理理解**：用户可选择`准确`、`部分准确`、`改成我的说法`或`不适用`。未经治理的 AI 观察不成为用户经验。
6. **下一次怎么做**：用户可选择`小范围尝试`、`保持原方法`、`停止某项做法`或`暂不形成结论`，并补充预期信号。
7. **确认与回访**：用户明确确认真实结果、`lessons[]`和完整复盘后才保存；复盘本身不保存回访。需要继续验证时，再逐问确认备选方案、预期信号与`reviewAt`，创建一条新的待观察判断。

只有确认动作可以把草稿写入结果或复盘。输入、快捷选项、展开依据、AI 观察、内观记录和回访日期变化本身都不能触发保存。复盘完成后生成回执，说明：

- 保存了哪条真实结果和哪次复盘。
- 引用了哪些资料、用户原话和证据定位。
- 绑定的是哪个章程版本。
- 当前尚未创建新回访；若用户随后创建待观察判断，再由新判断回执记录`reviewAt`。
- 哪些内容没有自动进入长期记忆、人生章程、个人本体或其他 Agent 上下文。

### 四个次级入口

首屏下方只保留四个简单入口：

| 入口 | 内容与责任 |
| --- | --- |
| **正在验证** | 等待真实结果的判断、承诺和用户已决定继续跟踪的小范围尝试；明确显示回访时间，不制造每日任务 |
| **等我复盘** | 结果已经回来、等待用户确认事实和解释的事项 |
| **成长记录** | 按`当时判断 → 真实结果 → 留下经验 → 下一次`展示历史，可追溯当时章程版本与来源 |
| **我的方向** | 展示人生章程当前版本与历史版本；`人生章程`只作为详情术语，不占据成长首屏 |

这些入口是浏览和回看方式，不改变“任何时候只有一个主要成长任务”的原则。

### 空状态、等待与来源变化

| 情境 | 首屏行为 | 保存边界 |
| --- | --- | --- |
| 尚未完成资料基线 | 说明知君还不够了解用户，引导添加资料或完成建档，不提供虚假的个性化建议 | 不创建个性化成长事项 |
| 没有成长事项 | 询问“最近有哪件事，你想在一段时间后回来检验自己的判断？”，可从近期资料选择或直接描述 | 用户确认判断、预期信号和时间后才创建 |
| 正在等待结果 | 显示判断、预期信号和回访时间，允许查看或修正；不制造签到和每日任务 | 保持`open`，不虚构结果 |
| 结果已到 | 成为首屏唯一主要任务，进入对话式复盘 | 用户确认事实后记录结果；复盘另需明确确认 |
| 复盘已完成 | 展示用户留下的方法和回执，可把下一次做法设为新验证 | 只有用户选择继续跟踪才创建新判断 |
| 来源变化或删除 | 标记`依据已变化，需要重新核对`，展开显示受影响内容 | 不继续把旧解释当作可信结论，不静默改写历史 |

若资料只能证明“回访时间已到”而不能证明结果，事项仍应请求用户确认事实，不能直接进入已复盘状态。

## 原型状态模型

V4 使用独立虚构状态，不修改公共 API：

| 对象 | 作用 |
| --- | --- |
| `OnboardingState` | 认识方向、起步顺序、当前章节、暂停和浏览状态 |
| `Source` | 资料名称、类型、作者关系、敏感等级和用途范围 |
| `ProcessingJob` | `uploaded / queued / processing / available / failed` |
| `ParsedArtifact` | 解析文本、OCR、转写、摘要和人物／组织／主题线索 |
| `InterviewSession` | 认识方向、当前问题和完成状态 |
| `InterviewAnswer` | 用户原话、问题、隐私范围和修改记录 |
| `EvidenceRef` | 来源、精确定位、摘录和证据类型 |
| `RecallableFact` | 可回到原件的事件、原话、人物关系或材料事实，不等于长期自我理解 |
| `LongTermMemoryCandidate` | 值得长期保留的候选内容、连接原因、不确定性、适用范围和治理状态 |
| `LongTermMemory` | 用户治理后的长期记忆、版本、依赖来源和本体影响 |
| `UnderstandingCandidate` | 候选理解、依据、不确定性、适用范围和治理状态 |
| `ReviewEvent` | 确认、修正、限定范围、拒绝或暂不保存 |
| `OntologyClaim` | 确认后的理解、来源关系、版本和本体层次 |
| `IntrospectionRecord` | 关联情境、三种内在声音、成为之向和保存范围 |
| `InnerVoice` | 用户原话、资料观察或知君推测及其独立治理状态 |
| `ReflectionPromotion` | 将情境内观升级为长期本体候选的二次确认 |
| `GrowthCharter` | `我的方向`当前版本与历史版本；创建判断时记录当时有效的章程 ID 和版本 |
| `GrowthDecision` | `正在验证／重要选择`；保存判断、选择、理由、信心、预期结果、证据与回访时间 |
| `GrowthDecisionOutcome` | 用户确认的`真实结果`（产品语义可简称 GrowthOutcome）；包含结果、补充说明、证据引用和记录时间 |
| `GrowthReview` | 用户确认的`成长复盘`；保存反思、留下的经验和`nextAction` |
| `GrowthTodayItem` | `本周最值得处理的事`；只从到期判断和待复盘事项中选择主任务 |
| `BoxRuntimeState` | 盒子连接、记忆服务、同步、存储和维护的虚构演示状态 |
| `TrustedDevice` | 演示设备、连接方式、最近通讯和撤销状态 |
| `SyncJob` | 手机分享、待确认同步、失败与重试的虚构任务 |
| `EgressReceipt` | 接收方、用途、必要片段、授权范围和调用结果回执 |

数据流必须保持：

```text
Source
    → ProcessingJob
    → EvidenceRef / RecallableFact
      ├→ LongTermMemoryCandidate → 用户治理 → LongTermMemory
      │    → UnderstandingCandidate / OntologyClaim
      └→ 支撑具体情境 ┐
用户直接描述 ─────────┴→ 用户确认的当时判断 → GrowthDecision
                              → GrowthDecisionOutcome
                              → GrowthReview
                              ├→ 可选的新 GrowthDecision
                              └→ IntrospectionRecord（可选情境旁路，不自动回写）
```

成长用户呈现与现有接口的映射必须固定：

| 用户呈现 | 现有底层对象／状态 |
| --- | --- |
| 我的方向 | `GrowthCharter` |
| 正在验证／重要选择 | `GrowthDecision` |
| 真实结果 | `GrowthDecisionOutcome`（随 `GrowthDecision` 返回） |
| 成长复盘 | `GrowthReview` |
| 本周最值得处理的事 | `GrowthTodayItem` |
| 等结果 | `GrowthDecision.status = open` |
| 待复盘 | `GrowthDecision.status = outcome_recorded` |
| 已留下方法 | `GrowthDecision.status = reviewed` |

`我的方向`页面通过现有章程历史响应读取`currentCharter`与`versions`，其中每个版本仍是`GrowthCharter`；原型不另建方向模型。

本轮不修改公共 API，也不新增独立的 `ActionExperiment` 模型。`小范围尝试`先保存为当前 `GrowthReview.nextAction`；只有用户选择继续跟踪，并确认预期信号与回访时间后，才通过现有创建判断能力生成新的 `GrowthDecision`。对应现有接口仍是章程读取／保存、判断列表／创建、记录判断结果、创建复盘和今日事项读取。

`InterviewAnswer`为候选长期记忆和候选理解补充用户解释，但不替代原始资料。证据展开、自动挑选唯一主任务、对话式草稿编排和内观记录属于高保真原型能力；它们没有对应的新增公共 API，文案不得暗示底层已经实现。`BoxRuntimeState`、`TrustedDevice`和`SyncJob`只服务于原型交互演示，不表示真实硬件状态。

删除或版本变化必须沿依赖关系向下标记影响。来源被删除后，相关理解和受影响的成长解释进入`依据已变化，需要重新核对`，不能继续作为确定事实或可信方法使用；历史判断与结果保留来源变化记录，不被静默重写。

原型必须把现有底座、V4 产品层目标和尚未交付能力分开，不能用高保真交互暗示生产能力已经存在。

| 层级 | 能力 | V4 表达原则 |
| --- | --- | --- |
| 现有资料底座可复用 | 白名单文件导入与大小校验；上传、排队、处理、完成、失败状态；失败重试；文档解析；图片与扫描 PDF OCR；音频 ASR；摘要、标签候选、实体与关系派生；资料版本；本地检索与证据问答 | 可以作为产品设计依据，但本原型不实际调用 |

## 关键点击链

### 资料先行建档

选择认识方向 → 从真实资料开始 → 选择虚构示例资料 → 标注作者关系 → 观察盒内处理 → 回答一个语境问题 → 查看两段依据 → 治理第一条候选 → 形成第一条长期记忆 → 支撑本体节点 → 查看朱砂回执。

### 今日候选记忆

今日知君 → 查看一条由两个时间点形成的候选长期记忆 → 回答适用范围 → 查看资料依据、不确定性和确认影响 → 明确确认 → 进入长期记忆 → 支撑本体节点 → 查看长期记忆回执。

### 记忆工作台

记忆 → 记忆工作台 → 查看盒内工作流与当前候选 → 核对候选 → 进入长期记忆 → 查看`原始资料 → 可回忆事实 → 长期记忆 → 本体`完整链路；或切换到原始资料，预览删除来源对记忆和本体的影响。

### 对话先行建档

选择认识方向 → 手边没有，先聊几分钟 → 回答访谈问题 → 得到“你的自我表达” → 被邀请补充相关资料 → 资料处理完成 → 形成有材料支持的候选长期记忆 → 用户治理 → 成为长期记忆 → 支撑本体。

### 结果已到 → 完成复盘

成长 → 打开唯一主任务`COO 任命 · 30 天结果已回来` → 回答一个关键问题 → 复盘卡实时更新草稿 → `查看依据` → 描述事实结果 → 查看知君的带依据观察、其他解释与反向问题 → 选择`准确／部分准确／改成我的说法／不适用` → 确认`lessons[]`与下一步 → 最终明确确认 → 保存结果与复盘 → 查看“尚未创建新回访”的回执。

### 没有事项 → 建立待观察判断

成长空状态 → 回答“最近有哪件事，你想在一段时间后回来检验自己的判断？” → 从近期资料选择一件事或手动描述 → 逐轮单问题形成背景、`options[]`、当前选择、当时理由、信心、预期信号和回访时间 → 用户明确确认 → 创建 `GrowthDecision` → 进入`正在验证`并显示等待结果状态。

### 已完成复盘 → 再次验证

打开已完成复盘 → 查看留下的方法 → 选择`将下一次做法设为新验证` → 确认小范围做法、预期信号和回访时间 → 用户明确确认 → 创建新的 `GrowthDecision` → 回到`正在验证`。若用户不选择继续跟踪，`nextAction`只留在原复盘，不创建新对象。

### 复盘中的可选内观

复盘出现具体价值张力 → 查看“可以打开内观镜，也可以直接完成复盘” → 选择打开或跳过；打开后依次探索本我、超我、自我并校准情境内观 → 返回原复盘与原问题 → 完成复盘。内观结果不自动改变真实结果、复盘结论、人生章程或个人本体。

### 升级为长期理解

打开一条情境内观 → 点击`这也是长期的我` → 查看将进入本体的候选内容和来源 → 第二次确认 → 自我表达或理想方向节点进入本体内环。

### 来源影响治理

记忆 → 原始资料 → 打开一份资料 → 删除 → 查看受影响的候选记忆、长期记忆、本体节点、成长解释和内观记录 → 明确确认 → 相关记忆、理解与成长解释标记为需要重新确认。

### 盒子通讯与边界

盒子 → 通讯与同步 → 检查可信设备与待同步资料 → 通过明确按钮查看或确认；盒子 → 权限与出盒 → 查看接收方、用途和全部必要片段 → 一次性明确授权 → 查看调用回执。两条路径都只演示预期交互，不连接或控制真实硬件。

## 视觉与交互原则

- 延续 V2/V3 的私人书房、宋体、朱砂印记、暖纸色和墨色体系。
- 建档阶段使用聚焦画布，隐藏复杂导航；成熟阶段恢复五个入口。
- 每个第一视口只出现一个主任务和一个主按钮。
- 今日首页优先呈现一条候选长期记忆，让用户先看见知君的资料整理劳动和治理边界。
- 成长首页采用桌面端“对话 65% + 复盘卡 35%”；复盘卡只汇总已经显示给用户的内容，并在确认前持续标记为草稿。
- 成长不出现成长分数、人格评分、签到、连续天数或道德化评价，也不以 14 天实验作为默认框架。
- 记忆页持续显示从原始资料到本体的六步链；本体页持续显示可返回的记忆地基。
- 盒子页和全局盒子状态始终标注`虚构示例`或`演示状态`，不使用会让人误认为已连接真实硬件的无条件成功文案。
- 结果卡只有形成可核对内容后才出现；上传、输入和检索阶段不显示空字段。
- 桌面端结果卡为情境侧卡；1024px 为覆盖式侧卡；移动端为底部抽屉。
- 知君默认短回应：复述当前理解、说明状态、提出一个关键问题；成长复盘每轮只推进一个问题。
- 只显示可验证阶段，不展示伪造思维链。
- 语音必须经过录音、实时转写、编辑和最终确认，不得自动提交。
- 删除、高敏感确认、Agent 授权和片段出盒必须使用影响预览与明确按钮，不能由一句自然语言完成。
- “原件不出盒”旁必须同时说明“问题与必要上下文片段可能出盒”，不能缩写成“所有数据只在本地”。

## 响应式与可访问性

- `≥ 1180px`：完整侧栏和桌面内容区；成长为 65% 对话与 35% 复盘卡双栏。
- `768–1179px`：窄侧栏；成长对话与复盘卡按上下顺序呈现，保持完整字段可见。
- `< 768px`：底部五项导航；建档与成长对话单列；复盘卡、结果和本体详情为底部抽屉；三瓣图改为顺序相同的分步卡片。
- 1440px、1024px、390px 均不得出现横向滚动。
- 主操作使用原生 `button`，表单拥有可见标签，状态变化使用 `aria-live`。
- Tab 可完成完整路径；焦点轮廓清晰；Escape 关闭模态、侧卡和抽屉并恢复触发点焦点。
- 状态不只依赖颜色表达；图标配文字或无障碍名称。
- `prefers-reduced-motion` 下停止呼吸、转场和图形动画。

## 验收标准

- 用户在 10 秒内理解知君为什么需要资料、原件在哪里、谁决定哪些理解留下。
- 成熟产品准确显示`今日知君／记忆／本体／成长／盒子`五个一级入口，桌面与移动端一致。
- 成长第一视口能直接回答“成长是什么、我现在做什么、做完得到什么”，且只有一件主任务和一个主要问题。
- 成长页显示`正在验证／等我复盘／成长记录／我的方向`四个次级入口；人生章程不占据首屏。
- 结果已到、没有事项、已完成复盘三条成长点击链均可走通，并分别到达回执、等待结果和新的`正在验证`状态。
- 复盘卡随回答实时更新，但确认前保持草稿；未经用户确认，不保存真实结果、复盘、长期方法或新的判断。
- 知君观察同时展示具体依据、其他解释和反向问题，且用户可选择`准确／部分准确／改成我的说法／不适用`。
- 小范围尝试先写入`GrowthReview.nextAction`；只有用户选择继续跟踪才创建新的`GrowthDecision`，不存在独立`ActionExperiment`。
- 今日首页第一视口出现一条候选长期记忆；确认前不参与未来回忆，也不支撑本体。
- 记忆页包含`记忆工作台／长期记忆／原始资料／持续议题`四个页签，并完整显示从原始资料到本体的治理链。
- 本体页显式显示长期记忆地基、受影响记忆和返回记忆工作台的入口。
- 盒子页包含`盒子概览／通讯与同步／资料处理／权限与出盒／维护`五个页签。
- 所有盒子在线、通讯、同步、处理、存储、系统和维护状态均明确标注为虚构演示；任何控件都不会调用真实硬件。
- 出盒说明准确表达：原件不出盒，但问题与完成任务所必需的上下文片段可能出盒，且发送前预览、明确授权、发送后留回执。
- 两次点击内可以开始导入资料或开始访谈；两条路径可换顺序并最终汇合。
- 没有资料依据时，知君不解释本我、超我、潜意识或稳定人格。
- 仅有访谈时只形成“用户自我表达”；两个证据点不足时不形成跨经历理解。
- 快捷按钮提交内容与可见文字完全一致，不补写用户没有说过的第一人称事实。
- 第一条确认内容先成为长期记忆，再正确支撑本体；拒绝或仅限本次的内容不进入长期本体。
- 三种内在声音分别显示来源并可独立确认、修正、限定或拒绝。
- 内观可打开、跳过并返回原复盘，不阻断成长闭环；情境内观默认不改变复盘、章程或本体，`这也是长期的我`必须触发第二次确认。
- 删除或更换来源后，受影响理解与成长解释正确标记为`依据已变化，需要重新核对`。
- 内观内容不会自动进入万象或其他 Agent 的上下文。
- 成长不出现成长分数、人格评分、签到、连续天数或道德化评价。
- 数据建档、长期记忆、本体确认、判断记录、真实结果、成长复盘和再次验证形成可追溯但职责分明的闭环。
- 成长重构不改变今日知君、记忆、本体和盒子的既有点击链，也不修改 V2、V3、生产前端或公共 API。
- 关键响应式尺寸、键盘导航、Escape、焦点恢复、Reduced Motion 和控制台零错误全部通过。
