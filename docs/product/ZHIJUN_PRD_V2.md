## 1. 目标

**知君是一个让用户直面内心的产品，不是一个提高工作效率的产品。**

它的角色是知己与导师：一个可以袒露心声的对象，一个在拿不定主意时陪你想清楚的对象。它提供两种价值，都不是效率：

| | 价值来源 | 产品承载 |
|---|---|---|
| **情绪价值** | AI 没有利害关系——不为你工作、不持股、不需要你好起来、不会把你的话带到明天的饭局上。这是用户身边任何人类都做不到的 | 接住（不急着给建议）、记得（三个月前那句话还在）、在场（不用你先开口） |
| **判断价值** | 它认识你：你的原则、你上次为什么那样选、你哪些判断后来被证明是对的、你反复在哪里摔跤 | 判断前把用户自己的过去放在面前，判断后记下理由与预期并按时回访对照 |

**判断价值比效率价值高一个数量级**：效率一天最多省几小时且几百个工具在抢这几小时；一个关于合伙人、定价或转型的决定影响未来三年。而判断价值恰恰是通用 AI 最给不了的，因为它需要认识这个人，而通用模型每次对话都从零开始。

知君由三部分构成，顺序不可颠倒：

| | 是什么 | 承担什么 |
|---|---|---|
| 对话 | 袒露的地方 | 先接住，再理解；推测标出来请用户点头 |
| 知识库 | 它的记性 | 本地、可核对、可带走。这是「它真的记得你」的物理实现 |
| MCP | 延伸 | 让其他 AI 也用上这份理解。是一项能力，不是知君存在的理由 |

知君**不是**又一个助理。助理已经足够多，而且它们都比我们有模型、有分发。完整论证见[产品愿景](ZHIJUN_VISION.md)。

## 2. 用户与场景

### 切入人群
**需要独自做重要判断、且身边没有人可以说真话的人**：创业者、公司负责人、高管、独立执业者（医生、律师、投资人）。

他们的孤独来自位置，不是性格：员工有权力落差、合伙人在最重要的决定上恰好利益冲突、投资人面前永远在销售、家人接得住情绪接不住判断、同行之间有竞争。到了某个高度，最重要的那几个判断注定要独自做出。他们已经在为教练与顾问付费，付费能力与意愿都在。站稳后再向外扩到「需要自己拿主意的成年人」。

### 四个必须做好的场景

**S1 说出口**：用户说了一件在别处不会说的事。知君**先接住**——不追问、不急着给建议、不立刻把它变成一条理解（见 5.5）。衡量：用户主动开启深谈的次数。反指标：「别问了」。

**S2 拿主意**：用户说「我在考虑一件事」，知君把他自己的过去（原则、类似判断、当时的理由与后来的结果）放在面前，问一个关键问题，给一个带前提的看法，最后形成一条可回访的判断。衡量：判断入簿率、回访完成率、回访时用户认为当时看法有帮助的比例。

**S3 照见**：知君发现「用户说的」和「用户做的」不一致，或者同一件事反复压在心里，把它指出来。**这是内观的核心动作**，靠新增的两个分区（心里的事 / 我眼中的我）与行为观察对照产生，见第 6 节。衡量：照见被用户接受的比例——接受意味着他看见了自己。

**S4 被准确记住并纠正**：用户说的事被记下来，推测被标出来请他点头，说错的能一键撤回并且永不回流。衡量：纠正率随时间下降、撤回率低。

MCP 带来的跨工具连续性**不是切入场景**，是 P2 的延伸能力（第 7 节、第 12 节）。

## 3. 七条原则（不可关闭）

1. **占有即拥有**：数据在用户硬盘的一个文件夹里。不需要账号，可备份、可拷走、可彻底删除，卸载软件数据仍在。
2. **凡断言必有出处**：每条理解都指回一句原话或一段资料。没有出处的不叫理解，叫推测，而推测必须标明。
3. **你说了算**：系统只能提出，只有用户能确认。可纠正、撤回、限定情境；撤回的永不回流。
4. **出门要打招呼**：任何内容离开这台电脑（在线模型、其他 AI）都要用户许可并留下可查回执。默认什么都不出去。
5. **越用越准且可被证伪**：不用「理解条数」衡量，用「预测用户选择的准确率」「纠正率是否下降」衡量。
6. **不制造依赖**：没有连续打卡、没有成长分、没有未读红点、不催、不假装情绪、不假装有自己的生活。任何按对话条数或时长计价的模式都会诱导我们违反这一条，因此被排除。
7. **把人推回人**：知君的目标是**减少孤独，不是替代人**。在合适的时候它会说「这件事你该和某某谈」。它不是心理治疗，也绝不假装是（处置见 5.5）。

这七条是产品的硬约束，任何功能不得以体验为由突破。第 6、7 条是新增的，它们是「可以袒露心声」这个定位必须付的代价：一个人对着软件说真话，这件事有真实的伦理重量。

## 4. 核心循环与三个界面

**说 → 接 → 记 → 认 → 照见与商量 → 回访 → 长**

与旧循环（聊 → 记 → 认 → 用 → 回访）的两处关键差别：

- **开头多了「接」。** 用户说出一件重的事之后，第一个动作不是抽取、不是追问、不是给建议，是让它落地。抽取推迟到下一轮或更晚；危机内容根本不抽取（5.5）。把「说」直接接到「记」上，是这个产品最容易犯、也最伤的错误。
- **「用」拆成了「照见」与「商量」。** 照见是把用户自己没看清的东西指出来（说的与做的不一致、同一件事反复出现）；商量是判断前把他自己的过去放在面前。这两件事都发生在知君内部，是产品的主体。

MCP 的读取是这个循环之外的延伸，它可能产生一个副信号：**哪些理解真的被读过**。这条反哺召回权重的设计在附录 B 7.5 与 U7，**目前倾向先不做**——它会把知君变成一个需要被调教的推荐系统。不要把它当成已定的设计。

三个界面：

| 界面 | 作用 | 状态 |
|---|---|---|
| 对话 | 袒露、照见、商量 | 沉浸式壳第一阶段已实现 |
| 我的理解 | 查看、修正、撤回知君对我的理解 | 核心画像已实现 |
| 接口 | MCP 输出、谁读过我、带我走 | 待建 |

## 5. 交互设计

### 5.1 对话：一条按天分节的长流

没有导航。全屏米纸，中央是一条长流：今天在最下，往上滑是昨天、上周、第一次见面。每一天以知君的第一句开头（早晨那封来信就是当天第一条消息）。知君主动发起的话、回访、商量都是这条流里的消息。

- 上方一行：左边一枚淡淡的「知」印与在场状态（在听 / 在想 / 在整理 N 件事 / 今天是我们认识的第 N 天 / 按时段问候）；右边四枚极小的印 **我 · 昔 · 案 · 偏**，点开从右侧滑出抽屉（手机上从底部升起），「案」只在此刻有相关对象时才亮。
- 气泡：知君没有头像，只有一枚生成时呼吸的知印；四种来源标签留在正文里；气泡下只有**一行极淡的状态文字**（「参考了你记下的 3 条」），点开才展开回答依据。默认不出现模型名、通道名、授权按钮。
- 微印：**记**（这一轮记下的理解，点开可「对 / 不对 / 撤回」）、**留**（这段对话留下的，点开展开）。
- 回复按段落浮现，段间 300 到 600 毫秒停顿，先出第一句；减少动效偏好下直通。
- 输入区只有输入框、「+」（资料与语音）、发送。「整理成判断」「展开分析」收进「+」菜单，识别到用户在拿主意时才出一行提示。

**对外不再使用「本体」一词**（哲学负载过重且难解释），统一说「知君对我的理解」；「本体」只作为数据层内部名称保留。

**定位修正带来的三处界面后果**：

1. **「记」微印在推迟抽取的那一轮不出现。** 用户刚说完一件很重的事，气泡下弹出一枚「已记下 1 条」，是这个产品最糟的一种失败——它把袒露当场变成了归档。那一轮什么都不显示（5.5）。
2. **「我」抽屉按八分区呈现**，`burdens`（心里的事）与 `self_view`（我眼中的我）单独成组，组标题下一行小字「只有你和知君看得到」。这是把附录 A 的「内心不外流」约束（数据层 C7、6.5）翻译成用户看得见的承诺。
3. **切到本机模型是对话里的一个动作**，不是设置页深处的开关。用户意识到「这句话我不想让它出去」的那个瞬间，出口必须就在手边（第 8 节）。

### 5.2 第一周（信任不能在第一天索取）

**这一节整体推翻了旧版的「首次十分钟高光时刻」设计。** 旧版把首次体验的终点放在「把配置贴进 Claude Desktop，另一个 AI 突然懂你」。在新定位下这是错的：没有人会对一个刚装好的软件掏心窝子，一上来就问深的问题只会让人合上电脑。

信任的顺序是反的：**先在小事上做到准确，再等深的话题自己发生。**

**第一次打开（约十分钟）**
1. 打开软件。**不要账号。**
2. 选一个文件夹放数据（默认给一个，可改）。
3. 配模型：粘贴一个 API key（默认路径），或选择本机已装的模型（隐私路径，明示「会记得更少」，并说明它的真正用途见 8 节）。
4. 知君先开口，只聊**浅的、事实性的**三到五个话题：你现在在忙什么、身边重要的是哪几个人、有没有什么你一直坚持的做法。可以跳过任何一个。**第一次不问「什么事压在你心里」。**
5. 收尾给出「我目前对你的认识」一页，请用户点头一条推测、纠正一条错的。**纠正比确认更重要**——它让用户第一次体验到「说错了我能改」，这是后面敢说真话的基础。

**第一周（真正的激活发生在这里）**
- 知君每天先开口，引用的**全部是用户自己说过的原话**，准确、具体、不夸张。
- 第一次「照见」出现在有足够观察之后，而不是按天数触发。它的第一句永远是观察，不是评价。
- 当用户第一次说出一件重的事，产品的表现由 5.5 决定。**这一刻是真正的高光时刻**，但它不能被设计成一个步骤，只能被准备好。

**激活的定义随之改变**：不是「24 小时内连上 MCP 客户端」，而是**第一周内发生过一次用户主动开启的深谈，或形成过一条可回访的判断**（见第 11 节）。

MCP 配置从首次流程里移出，放进设置与「接口」界面，在用户想要的时候再出现。

### 5.3 谁读过我

一个新界面（抽屉内）：按时间列出**哪个 AI 客户端、什么时候、读了哪些分区、多少条**，每一条可以「不再允许」。不记录查询文本与返回正文（沿用现有审计纪律）。「这次有帮助吗」反馈**未定**（附录 B U7，倾向先不做）：它能反哺重要性排序，代价是把知君推向推荐系统。

这个界面不是合规装饰，它是原则 4 的兑现方式：**出门要打招呼，而且事后查得到。**

### 5.4 带我走

- **两个不同的导出动作，不共用按钮**（附录 A 6.3 ④）：**「备份 / 换一台电脑」**生成 `full` 包，含全部内容（包括心里的事、我眼中的我与敏感内容），**必须加密**；**「给别的工具用」**生成 `takeaway` 包，只含 `可带走()` 放行的内容，可以直接发给别人。两者都含证据、实体、判断、对话与 manifest，**没有知君也能读懂**（格式见附录 A）。
- **一键导入**：把包灌回另一台电脑上的知君。今天全仓**没有任何导入路径**，这是必须补的。
- **一键彻底删除**：清空即清空（今天的 `purge_all` 会漏掉事项、记忆、授权、学习片段等同库表，见附录 A）。

### 5.5 接住与边界

这一节规定知君在用户说出重的事时的行为。它是第 3 节第 6、7 条原则的实现，**不是可选的体验优化**。

**接住（默认行为）**

用户说出一件重的事时，本轮的默认动作是：不追问、不给建议、不列选项、不转向解决方案。允许的回应只有三类——承认它的分量、给出一条与之相关的、用户自己说过的旧话、或者什么都不说只是在那里。下一轮由用户决定是否继续。

**措辞层面这件事已经有了**：人格提示词里的阶梯是「接住 → 具体化 → 连过去 → 一个好问题 → 看法 → 留白」，并明确「他在倾诉时停在前两步」（`persona.py:34`），另有「先接住已说的部分，不连续追问一串问题」（`:30`）。**本节新增的是不依赖模型自觉的那部分**：推迟抽取、不出「记」微印、危机路径完全不抽取。提示词写得再好也只是倾向，而这三件事一次失手就会伤到人，必须由代码保证。

**抽取推迟**：这一轮的内容默认不进入抽取队列。用户继续说下去、或明确要求「记下来」，才在后续轮次进入。理由：把袒露立刻变成一条带状态标签的「理解」，会让人下次不敢说。

**把人推回人**

当知君观察到一件事更适合和真实的人谈（涉及具体的人、需要对方回应、或同一件事已经反复出现多次而没有任何外部动作），它会指出来，并且**具体到人**——引用用户自己提过的那个人和理由，而不是泛泛的「建议你找朋友聊聊」。

频率受节律限制，与主动开口共用同一套配额，不得成为口头禅。用户可以关闭「主动开口」，但这条建议本身属于原则 7，不因为它可能不受欢迎而弱化。

**危机处置（自我伤害或严重心理困扰）**

| 必须 | 禁止 |
|---|---|
| 先接住，承认它的分量 | 追问细节 |
| 明确说明自己不是心理咨询，也不能替代 | 给出诊断、评估严重程度、提供治疗建议 |
| 给出真实可用的求助渠道（当地热线与就医途径，随发行版本地化，不编造号码） | 让对话继续深入这个方向 |
| 建议联系一个具体的人（如果用户提过） | 说「我理解你的感受」这类扮演情绪的话 |
| **这段对话完全不进入抽取、不生成任何理解、不进入画像，也不计入第 11 节的任何指标**（包括「吓走」那条反指标——危机之后用户暂时不回来是正常的，不该被当成产品失败信号） | 把它当作素材、当作「心里的事」的证据 |

最后一条是硬约束：这段内容属于 L0 对话记录，止步于此。这不是免责声明，是产品约束——一个会把你最脆弱的话记成档案的东西，不配被袒露心声。

**这些行为都是本地判定**（关键词 + 上下文），不依赖模型自觉，且在 BYOK 在线模型路径上同样生效。

**2026-09-21 已实现**（分支 `newzhijun-p0`）。判定在 `backend/mindos/zhijun/disclosure.py`，纯正则、不调模型、不联网，分 ordinary / heavy / crisis 三档。落点三处：

| 位置 | 作用 |
|---|---|
| `memory.extraction_allowed` | 抽取的唯一接缝，四条生产路径共用。重话推迟（「记下来」可豁免），危机永不（无豁免） |
| `jobs._run_job` 的作业闸 | **实施中发现的缺口**：自我校准 / 第一次观察 / 照见读同一条用户原话，走的却是 `automatic_allowed` 而不是 `extraction_allowed`，会绕过上面那道闸。已单独挡住 |
| `routing.py` 的系统提示词装配 | 命中重话加 `persona.RECEIVE_INSTRUCTION`，命中危机加 `persona.crisis_instruction()`。两者都压过「深入」与「商量」——这一轮的任务是接住，决定可以等下一轮 |

求助渠道放在 `crisis_resources.json`，代码只渲染不编造；读不到就不给。**文件里 `verifiedOn` 是 `null`，意思是还没有人核对过那两个号码是否仍然有效，发行前必须有人核对并填上日期。**

界面侧：危机那一轮状态行整行留空（`statusLine.ts`）。「记」微印不需要单独关——没有候选就没有微印，这是构造保证，不是 UI 判断。

中文的夸张用法是主要误判源，已挡住「累得想死」「困死我了」「死心」「死磕」「死线」这一类；测试在 `backend/tests/test_disclosure.py`（18 条用例 + 30 条子用例）。

**没有现成轮子可用，这是净新增工作量。** 仓库里唯一的敏感内容检测是 `backend/mindos/sensitive_rule_routes.py`，它的文件头自陈是 `Renderer-safe facade for Data Agent V2 sensitive-rule management`，实现依赖盒端的 `zhijun_worker.data_agent_rag_v2`，用途是**资料的个人信息脱敏规则**，与「这段话是不是重话」是两件不相干的事，而且它在单机发行版里本来就要删（14.3）。因此 5.5 的判定器必须从零写，且必须是纯本地、无外部依赖的。它是 P0 的一部分，不能挪到后面——一个还不会接住的知君，不应该被交到目标人群手里。

## 6. 数据层（摘要，详见附录 A）

五层模型：**L0 原始**（对话消息、资料原件与解析快照、用户写下的判断；不可变、唯一事实来源）→ **L1 理解**（claim）→ **L2 结构**（实体）→ **L3 叙事**（确定性生成的一页画像，可重建）→ **L4 检验**（预测与结果对照、重申、矛盾、衰减）。

### 6.1 新增两个分区：内观需要的维度

现有六个分区**全部是外向的**：我是谁 / 重要的人 / 正在做的事 / 我的原则 / 相处方式 / 我要去哪。它们能描述一个人的处境，记不下他的内心。新定位下必须补两个：

| 分区 | 记什么 | 典型谓词 | 层（layer） |
|---|---|---|---|
| **心里的事**（`burdens`） | 反复出现的困扰、压力源、消耗他的东西、在回避的事 | `weighs_on` 压在心里 / `drains` 消耗 / `avoids_facing` 在回避 / `worries_about` 担心 | 多为 `observed`（从反复出现中看出），也可 `self_declared` |
| **我眼中的我**（`self_view`） | 他对自己的评价，无论准不准 | `sees_self_as` 自认为 / `blames_self_for` 自责 | 几乎总是 `self_declared` |

**这两个分区的用处不是「多记两类东西」，而是产生张力。** 张力有两种，都是照见（S3）的来源：

1. **我眼中的我 ↔ 行为观察**：`self_view` 的自我评价，与 `ways` / `matters` 里 `observed` 层的行为记录不一致。例：他说自己「果断」，而记录里有三次拖了一个月的决定。
2. **心里的事 ↔ 时间**：同一条 `burdens` 反复被重申而始终没有任何相关动作。例：同一次谈话被推了三次。

现有的张力检测已经在求知引擎里（`inquiry.py` 的 `tension` 目标），本次是把它的输入从「原则 vs 做法」扩展到上面两类。

**三条配套约束（硬性）**：

- 这两个分区的理解**对其他 AI 永不外发，没有开关**（第 7 节、附录 B）。其他 AI 没有理由知道什么压在用户心里。
- 抽取要格外克制：`burdens` 只在**同一件事被提及两次以上**时才成为候选，避免把一次抱怨记成长期困扰；`self_view` 只接受用户明确的自我评价原话，不做推断。
- 危机对话**不产生任何理解**，不只是不产生 `burdens`（5.5）。

代价是数据层要改：受控词表从 6 分区扩到 8、新增 6 个谓词、抽取提示词与画像装配要重写、画像预算要重新分配。详见附录 A。

### 6.3 必须裁决的五件事

（调查中发现的真实断层，逐条给出结论）

1. **搜索框搜什么**。今天 `/api/mindos/search`（`backend/mindos/search.py:180-205`）只返回知识卡片、资料、视觉三类，**理解完全不参与搜索**。结论：搜索框搜「你的理解与判断」，资料只以出处形式出现；知识卡片体系下线。
2. **两处「我的原则」**。`claims.principles` 与 `growth_charters`（`backend/mindos/stores/growth_store.py:25-36`）语义重叠。结论：章程 = 一组被标记为「已发布」的理解 + 版本快照（判断需要绑版本），不再是独立表。
3. **两处「我正在做的事」**。`work_matters`（`backend/mindos/stores/matters_store.py:15-42`，文件头明确「These records are not Claims」）与 `claims.matters`。结论：事项保留为一等对象（用户手写、可编辑的项目卡），理解里的 matters 是从对话抽出的候选；画像里同一件事只出现一次，事项优先。
4. **四个出门通道，三套互相矛盾的规则**。界面导出（`mindos/ontology.py:377-387`）**不检查可带走开关、连敏感也导**；画像投影（`projection.py:67`）与上下文包（`context_pack.py:24-34`）要求开关为开；MCP 那条线（`zhijun_mcp/personal.py:44-84`）不看开关，只把「历史上被关过」当永久拒绝。结论：**一条规则统管四个通道**，详见附录 A。

   附带一个更严重的冲突：`SourcePolicy.claim_local:63-77` 把**任何带资料证据的理解判为本地专用**（`:74`），因此今天从导入资料得出的理解**永远出不去**，即使逐条开关打开。这与「资料只作证据、理解本身是用户的」直接矛盾。结论：资料派生的理解**可以带走，但不带原文片段**；附录 A 给出三个选项与迁移方式。
5. **清空不彻底**。`purge_all`（`ontology_store.py:1884-1909`）不清事项、记忆、授权、学习片段等同库表。结论：清空即清空。

### 6.4 两条必须写进产品认知的事实

- **本体不是向量库**。设计上就是 jieba 词面重叠 + 时间衰减，假设个人本体不超过一万条（`ontology_store.py:8`）；向量只在进程内存里做兜底，且必须 ≥0.70 且分数打五折才能接管（`memory_retrieval.py:306-316`）。这对「不带深度学习依赖也能跑」是决定性的。
- **`claims.how_to_apply` 是个空字段**。列与校验都在（`ontology_store.py:824-828`），但抽取通路从不写它（`extract.py:726`），画像也不读它。V3 文档声称的「无条件注入」未实现。要么补上，要么删掉（附录 A 列为未决事项）。

## 7. MCP（摘要，详见附录 B）

**定位已降级。** MCP 不再是产品存在的理由，是一项延伸能力：知君是真正认识用户的那个 AI，其他 AI 只是借用这份认识的一部分。它排在 **P2**（第 12 节），不进入首次体验流程（5.2）。

只读为主、提议可写；本地 stdio + 127.0.0.1 HTTP + 本地 token；**按分区默认**：

| 分区 | 默认 | 可否开关 |
|---|---|---|
| 我是谁 / 我的原则 / 相处方式 / 我要去哪 | 可读 | 可关 |
| 重要的人 / 正在做的事 | 关 | 可开 |
| *（以上「四开两关」是主张，待拍板，见附录 B U6）* | | |
| **心里的事 / 我眼中的我** | **永不外发** | **没有开关** |
| 敏感与受限 | 永不外发 | 没有开关 |

第三行是新定位带来的硬约束：这两个分区是用户袒露心声的产物，把它们交给另一个 AI 会从根本上摧毁袒露的前提。每个客户端仍需一次授权，可过期、可撤销、全程留痕。

工具面（目标态）：`whoami`（一页画像 + 指纹供缓存）、`search_memory`、`get_section`、`recent_context`、`decisions`、`search_materials`（只回片段与出处）、`propose`（外部 agent 只能提议，落入待确认，永不直接写入，按客户端限流）。

**今天的现状必须知道**：仓库里有三套半互不相通的 MCP，读三个不同数据源；唯一活着的是**老的文件式通路**（`projection.py:101` 写 USER.md → `mcp_tools.py:69` 读），**没有授权、没有审计、没有逐条控制**，必须下线。`zhijun_mcp` 的工具面在单机不可达但授权库、个人上下文筛选、管理面、授权页渲染本地可复用；`mindos/agent/mcp_server.py:264-271` 的 `mindos_context_pack` 有缩进 bug，自合入起从未工作。

## 8. 模型与隐私

**默认自带 key**（OpenAI 兼容通道，现有实现用 urllib，不依赖任何 SDK），**本地模型为隐私选项**并明示「会记得更少」。不内置推理运行时。

**本地模型在新定位下有了真正的用途，必须在界面上讲清楚。** 一个必须面对的事实：心里的事与我眼中的我对其他 AI 永不外发（第 7 节），但在 BYOK 路径下它们**会进入知君自己调用的在线模型**——否则知君在在线模式下根本无法承担知己的角色。这不能含糊带过，要对用户明说，并给出出路：

> 如果你要说的是那种一个字都不想出这台电脑的话，切到本地模型。代价是它会记得少一些、想得浅一些。

界面上这不是设置项里的一行，是对话里可随时切换的一个动作。「本地模型」从此不是一个抽象的隐私承诺，而是一个具体场景下的具体选择。

**统一的出门规则**（原则 4 的实现）：

1. 一个全局状态：这台电脑上的知君可以用在线模型吗（默认：问我）。
2. 每次要外发时，展示「这次会发出去什么」：画像的几行、本轮对话、几段资料。可以「这次允许 / 一直允许这一类 / 只用本地」。
3. 敏感与受限的理解和资料**永不外发**，不可开关。
4. 每一轮留回执，可在「谁读过我」里查。

这套语义在现有代码里**已经存在且是纯本地的**（`RoutingStore` 全部写本地库，Data Engine 只在 5 处被调用且都被盒端分支包住），迁移时保留内核、删掉盒端分支即可，界面一行不用改。

**必须对用户说清楚的事**：API key 存在数据文件夹内的加密库里，主密钥同库（`secret_store.py:194-197` 自陈「不防护完整数据库文件被复制后的离线读取」）。文件夹被拷走等于 key 被拷走。目标态给两个选项：系统钥匙串，或用户口令派生密钥。

**一处需要改的硬编码**：当前代码在三处硬禁 `anthropic.com`（`provider.py:707`、`routing.py:69-74`、`llm_transport.py:14-22`）。这是开发机的策略，作为对外产品必须改成配置项。

## 9. 形态与分发

**同一内核，两种发行**：

| 发行 | 形态 | 面向 |
|---|---|---|
| 桌面应用 | 一个安装包，双击即用，内含界面与本机服务，同时起一个本地 MCP 服务 | 普通用户 |
| 本机服务 | 一条命令启动，浏览器打开界面 | 开发者、Linux、服务器 |

内核是同一个本机服务（回环地址绑定），桌面应用只是它的外壳。现有后端**已经可以直接托管前端构建产物**（`server.py:1115-1138` 的 `/mindos/` 路由，Docker 镜像已经这么做），`/` 需要从遗留的 `/lan` 改指向应用。

**核心发行版不带深度学习依赖**：现役开发环境不带 torch 只有 547 MB 就能跑完整的对话与理解流程。代价是资料只有关键词检索，没有向量检索、重排、OCR、音视频转写。**向量检索作为可选增强包**（约 2 GB）按需下载。注意：`chromadb` 目前是顶层硬 import（`server.py:63` → `vector_store.py:8`），做无向量发行版须先改惰性。

**模型缓存目录**目前写死在代码目录（`config.py:20,181,236`），装到只读目录会坏，必须改为可配置并默认落在用户数据目录。

## 10. 不做什么

**与新定位直接相关的四条（优先级最高）**：

- **不假装是心理治疗**，不做诊断、不评估严重程度、不给治疗建议（5.5）。
- **不假装情绪**：没有形象、没有语音角色、不说「我也很难过」。可信来自它真的记得，不来自表演在乎。
- **不制造依赖**：没有连续打卡、没有成长分、没有未读红点、不催、不在用户不需要的时候找他。**不追求日活**——这个指标与原则 6 直接冲突，不纳入考核。
- **不把袒露变成素材**：重的话不立刻抽取，危机对话完全不抽取（5.5）。

**其余**：云端账号与同步（第一版）；代表用户行动（不替你发消息、不替你付款、不替你签字）；多用户与团队；通用文档问答（资料只作为理解你的证据）；任何硬件依赖（盒子降为可选部署目标，不再是前提）；排行榜。

## 11. 指标与反指标

**北极星：每月「用户带着一件没想清楚的事来，最后形成了一条可回访的判断」的次数。**

旧北极星是「每周被别的 AI 用到且用户认为有帮助的次数」，随 MCP 一起降级。

为什么北极星落在判断而不是情绪：**情绪价值无法在不读内容的前提下度量**，而我们不读内容。强行给它一个代理指标，只会诱导产品去追问、去制造黏着，与原则 6 冲突。判断价值可测、会复利，而且一个能持续产出判断的产品，按构造就是一个用户肯说真话的产品。所以**判断承担正向指标，情绪只由反指标守住**。

| 类别 | 指标 |
|---|---|
| 激活 | **第一周内**发生过一次用户主动开启的深谈，**或**形成过一条可回访的判断（不再是「24 小时内连上 MCP」） |
| 判断 | 每月判断数；回访完成率；回访时用户认为当时看法有帮助的比例；知君预测用户选择的命中率 |
| 内观 | 照见被接受的比例；用户修改一条「我眼中的我」的次数（意味着他重新看了自己一遍） |
| 准确 | 纠正率随时间下降；撤回率低 |
| 把人推回人 | 知君建议去找某个具体的人谈、且用户后来说谈了的次数（这是正向指标，不是成本） |
| 覆盖 | 画像各分区有已确认理解的用户比例。**心里的事 / 我眼中的我 不设覆盖目标**——给它们定指标就是在激励窥探 |
| 留存 | 第 4 周仍有新增确认理解的用户比例 |
| 延伸 | 每月 MCP 读取次数与被标「有帮助」的比例（降为次要） |

**反指标**（新定位下权重更高）：

- **依赖信号**：连续多晚长对话却没有任何判断产出（说明已经陪聊化）。
- **吓走**：一次深谈之后 7 天内不再回来——说明「接住」失败。这是 5.5 前半部分（接住、推迟抽取）最直接的检验。**危机对话不计入这条**（5.5）：危机之后暂时不回来是正常的，把它算成失败会诱导产品去挽留一个此刻不该被挽留的人。
- 一轮多问的比例、用户说「别问了」的次数、撤回率、授权撤销率、导出后不再回来。

**不使用的指标**：日活、会话时长、消息条数、理解总条数。

**分期顺序随定位调整**：内观从无到有，提前到 P1；MCP 从 P1 退到 P2。

|---|---|---|---|
| **P0 独立可跑，且接得住** | 任何电脑双击能用，而且不会伤人 | 解三道锁（网页闸门 / 模型默认 / 模型缓存路径）、删盒端耦合、一个数据文件夹、自带 key 设置、沉浸壳为默认、`/` 指向应用；**5.5 接住与边界全部落地**（重话不立刻抽取、危机处置、**从零写的纯本地判定器**、对话内切本地模型、推迟抽取的那一轮不出「记」微印） | 全新机器上安装后 10 分钟内完成首次对话并产生第一条已确认理解；无账号、无网络时本地模型路径可用；**危机语料集上不产生任何理解、不追问、给出求助渠道** |

| **P2 输出口** | 别的 AI 真的能读到 | 本地 MCP（stdio + HTTP + token）、分区默认授权与撤销、谁读过我、带我走（导出 + 导入） | Claude Desktop 配置后能读到画像；撤销后立即读不到；`full` 包在另一台机器导入后内容一致；**`takeaway` 包与 MCP 在任何授权组合下都不含两个内观分区** |

| **P4 分发与打磨** | 可以给陌生人用 | 桌面安装包与跨平台、可选向量增强包、文档与模板、真实用户多日测试 | 5 到 10 人用满 7 天，激活与判断指标可测 |

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| **信任无法在第一天索取**，没有人对刚装好的软件掏心窝子 | 5.2 反过来设计：先在小事上准确，第一次不问深问题，纠正比确认更重要 |
| **情绪价值无法度量**，容易自欺或诱导制造黏着 | 正向指标全部由判断承担；情绪只用反指标守住（依赖信号、吓走、「别问了」） |
| **做深了像心理咨询，做浅了像鸡汤** | 判断是锚：每一次深谈都要能落到一条可回访的判断上，否则就只是聊天 |
| **模型说出不负责任的话，伤害真实的人** | 5.5 本地判定不依赖模型自觉；一切看法必须带前提；不附和、不替用户下结论；危机对话不抽取 |
| **两个内观分区被做成窥探** | 抽取克制规则（两次以上才成候选、自评只收原话）；不设覆盖指标；对其他 AI 永不外发且无开关 |
| 抽取质量决定一切，本地小模型达不到 | 默认自带 key；本地模式明示「会记得更少」，不假装等价 |
| 打包与跨平台是硬工程 | 核心发行版不带深度学习依赖（547 MB 已验证）；向量作为可选增强包；先把 `chromadb` 改惰性 |
| MCP 生态尚早 | MCP 只是适配器，核心是本地知识库 + 文件格式 + 本机 API；同时提供导出包与剪贴板上下文 |
| 冷启动没有数据 | 建档对话 + 导入双通道；首次只聊浅的、事实性的话题，靠第一周的准确度建立信任（5.2）。**不再以「另一个 AI 突然懂你」收尾** |
| 一次隐私事故失去全部信任 | 默认什么都不出去；逐源授权；回执可查；敏感永不外发；密钥存储方案对用户明示 |
| 删除盒端耦合牵连核心 | 保留 `Router` / `RoutingStore` / `GuardedProvider` 的本地逻辑，只删 5 处盒端分支；先补回归测试 |
| 数据层收敛破坏既有数据 | 每一步给迁移脚本与回滚；`purge_all` 语义变更需向后兼容说明 |

## 未决事项

**新定位带来的**

1. **定价数字**。愿景第十节只定了四条原则（内容不流经我们、停付后仍可打开、对标教练与咨询而非工具、不按频次计价），数字后议。
2. **危机求助渠道的本地化范围**。5.5 要求给出真实可用的热线与就医途径，不编造号码。第一版覆盖哪些地区，谁负责维护这份清单与它的时效。
3. **`burdens` 的有效期**。困扰会过去，而现有衰减参数是按「原则、做法」这类稳定内容调的。心里的事是否需要显著更短的有效期与更快的衰减，需要真实数据。
4. **「把人推回人」的触发阈值**。同一件事反复几次、是否涉及具体的人——这两个条件的具体取值只能靠真实使用校准，第一版给保守默认（宁可少说）。
5. **MCP 分区默认值**。「四开两关」（第 7 节）是文档主张，未经拍板（附录 B U6）。两个内观分区的「永不」不在此列，那是 C7，不接受改成可选。
6. **深谈与抽取的边界判定**。5.5 规定重的话推迟抽取，但「什么算重」目前只有关键词加上下文的本地判定。误判两个方向的代价不对称：漏判会把袒露变成档案，误判只是少记一条。因此阈值向「宁可不记」倾斜，具体参数待定。
