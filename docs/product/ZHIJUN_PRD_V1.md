## 0. 文档定位与权威关系

本文定义“知君”从现有个人记忆库代码演进为个人本体 Data Agent 的产品目标、体验、领域对象、工程边界、发布门禁和 Beta 验收标准。

本文不是从零规划一个新系统。上述 Codeup 仓库是唯一开发底座和未来主仓：

1. 现有解析、OCR、ASR、资料版本、派生任务、混合检索、知识卡片、问答、治理、Agent 接口、Electron、Web 和移动采集能力，必须优先复用或改造。
2. 新的个人本体、成长闭环与知君角色能力在现有代码上增量建设，不创建相互竞争的第二套产品工程。
3. 现有 Wiki、知识卡、摘要、关系图和向量索引可以继续存在，但只能作为候选、工作区或可重建投影，不能成为个人本体权威事实源。
4. 任何与“原件不出盒”、用户治理权、最小出盒、删除语义和 Agent 权限相冲突的旧实现，在进入真实用户 Beta 前必须完成迁移或停用。

本文完成评审后，替代“把知君等同于个人知识库或通用 RAG”的产品定义。底层确定性语义仍由 CentaurOS Canon、ADR、Schema 和安全规范负责。

## 1. 执行摘要

### 1.1 产品定义

> 知君是运行在半人马AI私人记忆盒子上的个人本体 Data Agent。它把用户日常零碎的数据治理成一个可核对、可纠正、可持续成长的“我”，先成为一面真正懂用户的镜子，再成为有边界的良师益友，最终为用户的专属 Agent 提供可信的个人上下文。

知君不是云盘、笔记软件、聊天搭子或替用户做主的数字人。它的独特价值来自四件事同时成立：

- 它长期理解的是同一个人，而不是一次会话。
- 它的事实理解能够回到原始证据并接受用户纠正。
- 它明确区分现实自我、用户自述、理想自我和系统推测。
- 它能够把经历转化为判断复盘和下一步成长行动。

### 1.2 核心问题

目标用户并不缺少资料，也不缺少模型。他们缺少的是一个由本人掌控、可以穿越时间和应用的长期自我理解系统。

今天的数据散落在文档、聊天导出、照片、录音、项目资料和脑海里。传统工具能保存或搜索，但不能可靠回答：

- 我为什么总在类似情境下做出相似判断？
- 某段关系、某个项目或某次承诺的完整来龙去脉是什么？
- 哪些原则是我明确认同的，哪些只是模型对我的推测？
- 我想成为怎样的人，而我最近的行为与它有什么差距？
- 另一个 Agent 在代表我工作时，依据的是哪部分真实、有效且获授权的我？

内部产品命题：

> “把个人日常零碎的数据整理成一个完整的、能够帮助用户实现自我成长的另一个 AI 的自己。”

### 1.3 V1 核心选择

| 维度 | V1 决策 |
|---|---|
| 首发用户 | 企业主与核心决策者 |
| 本体边界 | 全人本体，先从事业与高价值判断切入 |
| 核心闭环 | 判断与成长复盘 |
| 角色路径 | 镜子 → 良师 → 分身 |
| V1 角色深度 | 镜子正式可用；良师 Beta；分身不代表用户行动 |
| 默认入口 | 今日页 + 随处与知君对话 |
| 主动节奏 | 重要事件触发 + 每周复盘 |
| 数据采集 | 主动记录、导入、拍照、录音和指定目录本地整理 |
| 交互形态 | 文字为主，支持语音输入；实时语音和数字人不作为门禁 |
| Beta 方式 | 顾问式陪跑建档，5 → 10 → 20 人扩容 |

## 2. 目标用户

### 2.1 首发 Persona

首发用户为中国大陆 18 岁以上的企业主、创业者和承担独立判断责任的核心决策者。职业头衔不是唯一标准，入选用户必须同时满足：

1. 数据敏感：资料、关系、交易或判断泄露会造成明显损失。
2. 上下文密集：好判断依赖长期关系、历史和隐性背景。
3. 决策独立：本人必须对结果承担责任。
4. 单位时间价值高：一次关键判断或一小时节省具有显著价值。

首批 Beta 用户还必须满足：

- 对导入资料拥有合法控制或处理权限。
- 每周至少存在一个可以记录、跟踪或复盘的真实判断。
- 愿意完成本体候选确认、纠错和每周复盘。
- 理解“原件不出盒，但必要上下文片段可能发送给云端模型”。

### 2.2 核心 Jobs to Be Done

当我需要做出重要判断时，我希望知君能还原相关人物、项目、历史承诺和类似案例，使我不因遗忘或信息割裂重复犯错。

当一个行动产生结果时，我希望知君帮助我比较当初的依据、信心和真实结果，让经验转化为可复用的判断原则。

当我反复表达某种原则但行为与它偏离时，我希望知君在合适的时机提醒我，并允许我判断是行为需要改变，还是原则本身已经变化。

当其他 Agent 需要理解我时，我希望它们只获得完成任务必需、经过我授权且可以追溯的个人上下文，而不是复制我的全部资料。

### 2.3 用户故事

- 作为企业主，我希望快速记录一次关键判断及其依据，以便未来能对照真实结果复盘，而不是只记得事后解释。
- 作为高价值决策者，我希望看到知君对我的每项事实理解来自哪里，以便我决定相信、纠正或拒绝。
- 作为长期用户，我希望区分“我现在是什么样”和“我想成为什么样”，以免系统把愿望误当成事实。
- 作为资料所有者，我希望查看每次模型出盒使用了哪些片段、为了什么目的、发送给谁。
- 作为万象用户，我希望新 Agent 能理解我的方法和边界，但不能直接读取全部原件或自行扩大权限。

## 3. 产品目标与非目标

### 3.1 V1 目标

G1. 建立可信个人本体：把多来源资料转化为有证据、状态、时间和隐私等级的实体与声明。

G2. 交付首次“被真正理解”的时刻：用户能看到一项跨来源、准确且有出处的个人理解，并能立即纠正。

G3. 跑通判断成长闭环：至少支持背景、选项、选择、依据、行动、结果和复盘的完整生命周期。

G4. 建立有边界的良师体验：知君可以发现模式、提出反向问题和建议，但不能把推测包装成事实或替用户作决定。

G5. 成为其他 Agent 的个人上下文底座：通过 CentaurOS 权限求交后的 Context Pack 提供最小必要上下文。

G6. 证明数据与信任承诺：原件留在盒内，必要片段受控出盒，全部调用可查看、可审计。

### 3.2 V1 非目标

- 不建设通用云盘、团队知识库或大众笔记产品。
- 不自动连接邮箱、日历、聊天账户和云盘。
- 不进行常开录音、持续位置追踪或环境感知采集。
- 不提供心理诊断、治疗关系或危机干预替代。
- 不把知君包装成无所不知、绝对正确或具有道德权威的“完美人格”。
- 不允许知君代表用户发送消息、签署文件、付款、发布或作出外部承诺。
- 不交付实时语音陪伴、数字人形象、家庭共享或组织共同本体。
- 不让模型、知识卡、Wiki、图谱或向量索引成为第二事实源。

## 4. 产品原则

### 4.1 先知，后君

知君首先必须准确地“知”：知道依据、边界和不确定性。只有在长期准确、可纠正的基础上，才有资格以良师益友的方式提出挑战或建议。

### 4.2 用户拥有最终解释权

模型可以提出候选、发现冲突和建议复盘，但只有用户能够确认、纠正、替代、撤回或重申个人事实、原则与理想自我。

### 4.3 四层自我不能混淆

产品必须在数据、界面和模型 Prompt 三层区分：

| 自我层 | 含义 | 默认治理 |
|---|---|---|
| 现实事实 | 有来源支持的经历、关系、事件和行为 | 候选后由用户确认 |
| 自我叙述 | 用户对自己的明确表达、偏好和解释 | 标记为用户陈述 |
| 理想自我 | 用户确认的愿景、原则、边界和目标 | 只能由用户创建或批准 |
| 系统推测 | 模型发现的模式、假设和可能解释 | 永远显示为待验证候选 |

### 4.4 建议必须比结论更谦逊

事实型回答必须引用证据；成长建议必须说明引用了哪些已确认事实或人生章程，并提供其他可能解释。用户可以选择“不适用”“不要再提醒”或“这条原则已经变化”。

### 4.5 陪伴不制造依赖

知君不声称拥有情感、意识或排他关系，不贬低用户身边的人，不用连续签到、羞耻、恐惧或失去关系等方式提高留存。

### 4.6 原件不出盒

原件、完整资料库和可重构原件的全量衍生物不进入公司或模型云。使用外部模型时，只发送完成当前任务必需的问题和上下文片段，并在发送前展示范围。

## 5. 北极星指标与成功标准

### 5.1 北极星指标

**每周可信成长闭环用户率**

分母：已完成建档并在该周具备至少一个可复盘判断、目标或承诺的 Beta 用户。

分子：该周完成一次成长复盘，并同时满足：

1. 查看至少一项带证据的观察或模式。
2. 对知君的理解完成确认、纠正、拒绝或补充。
3. 形成至少一个由用户确认的下一步行动、实验或停止事项。
4. 该复盘和行动被可靠保存，可在后续记录结果。

Beta 最后连续四周目标：不低于 60%。

### 5.2 Beta 指标

| 指标 | 目标 | 测量方式 |
|---|---:|---|
| 7 日激活率 | ≥ 80% | 20 人中完成建档、首次导入、5 条确认和首次可信对话 |
| 首次被理解时刻中位数 | ≤ 60 分钟 | 从首次导入完成到用户确认第一项跨来源有效理解 |
| 事实型回答带出处率 | 100% | 事实句必须映射 EvidenceRef |
| 引用与结论一致率 | ≥ 95% | 人工金标集双人复核 |
| 成长建议可追溯率 | 100% | 每条建议关联 Confirmed Claim 或人生章程版本 |
| 良师建议有帮助率 | ≥ 70% | 用户选择“有帮助/部分有帮助/无帮助” |
| 每周可信成长闭环用户率 | ≥ 60% | Beta 最后连续四周 |
| 4 周核心留存 | ≥ 60% | 连续四周至少三周完成可信使用 |
| 未授权出盒 | 0 | Egress 审计与安全测试 |
| 覆盖用户确认事实的模型写入 | 0 | 状态机与审计事件 |
| P0/P1 数据安全问题 | 0 | 发布门禁 |

### 5.3 反指标

- 用户因提醒过度主动而关闭全部通知的比例。
- 用户认为知君“把推测当事实”的反馈次数。
- 候选确认负担、批量忽略率和连续待办积压。
- 无引用却表现确定的回答次数。
- 建议让用户感到被评判、被操控或被替代的反馈。

## 6. 知君角色模型

### 6.1 Level 1：镜子

V1 正式能力。

- 记住用户明确交付的数据。
- 还原人物、项目、事件、承诺和时间脉络。
- 用证据回答“发生了什么”和“我当时如何判断”。
- 展示冲突、过期和未知，不替用户消除歧义。
- 接受纠正并确保旧理解不再进入回答和 Agent Context。

### 6.2 Level 2：良师益友

V1 Beta 能力，默认可关闭。

- 在足够证据下识别反复出现的判断模式。
- 对照人生章程、目标和真实行动指出一致或偏离。
- 使用苏格拉底式问题帮助用户重新审视假设。
- 给出小规模、可逆、可验证的行动建议。
- 后续主动询问结果并帮助形成复盘。

标准回应结构：

1. 我观察到什么。
2. 依据是什么。
3. 还有哪些可能解释。
4. 我想向你确认什么。
5. 如果你愿意，可以尝试什么。

### 6.3 Level 3：分身

不属于 V1 用户能力。

V1 只建设为未来分身准备的可信 Context 接口。任何代表用户表达、发送或行动的能力必须在后续版本另立 PRD、权限模型和发布门禁。

## 7. 个人本体产品模型

### 7.1 权威链

数据链路固定为：

原件版本 → 解析产物 → 精确证据 → 实体/声明候选 → 用户治理 → 已确认本体 → 档案/搜索/图谱/对话/成长投影。

任何搜索结果、摘要、知识卡或模型回复都不能逆向覆盖已确认本体。

### 7.2 核心对象

| 对象 | 产品语义 |
|---|---|
| PersonalVault | 单一自然人的数据、密钥与权限边界 |
| Source | 用户记录或导入的一份逻辑资料 |
| OriginalObjectVersion | 盒内不可变原件字节版本 |
| SourceVersion | Source 与原件版本的语义映射 |
| ParsedArtifactVersion | 可重建的 OCR、ASR、解析和结构化结果 |
| EvidenceSpan | 可以精确定位和校验的证据片段 |
| Entity | 我、人物、组织、项目、地点、主题、事件等稳定对象 |
| EntityAlias | 实体别名、旧称、简称和消歧线索 |
| Claim | 关于 Entity 的原子声明，包含时间、来源、隐私和治理状态 |
| ClaimEvidence | Claim 与支持、反驳或背景证据的关联 |
| ReviewTask / ReviewEvent | 用户确认、拒绝、纠正、替代、撤回或重申的过程 |
| GrowthCharterVersion | 用户确认的人生愿景、原则、边界、目标和复审时间 |
| DecisionEpisode | 一次判断从背景到结果和复盘的完整记录 |
| GrowthReview | 一次周度或专题成长复盘 |
| NudgePolicy / NudgeEvent | 主动提醒的授权、触发、展示和反馈 |
| Projection | 档案、时间线、图谱、搜索索引和今日页等可重建视图 |

### 7.3 四层自我字段

Claim 和成长对象必须拥有 selfModelLayer：

- observed：来源支持的现实观察。
- self_declared：用户明确陈述的自我理解。
- aspirational：用户确认的理想自我、价值观、目标或原则。
- hypothesis：模型或系统提出、尚未确认的推测。

answer、projection 和 agent_operation 默认只能读取 confirmed 且符合用途权限的 observed、self_declared 和 aspirational；hypothesis 只可用于 review。

### 7.4 DecisionEpisode

一次判断至少包含：

- 判断主题与发生时间。
- 相关人物、项目、目标和来源。
- 当时可见的背景与约束。
- 考虑过的选项。
- 用户最终选择。
- 当时的理由、关键假设和信心区间。
- 预期结果与观察期限。
- 下一步行动或承诺。
- 实际结果。
- 事后反思与可复用原则候选。

模型可以帮助结构化用户记录，但选项、选择、理由、信心和结果必须由用户确认。

### 7.5 GrowthCharter

人生章程不是一次性问卷，而是可版本化、可回顾的用户授权目标模型。至少包括：

- 我想成为什么样的人。
- 当前最重要的生活与事业角色。
- 我确认的长期原则。
- 不应由 AI 替我决定的事项。
- 当前阶段目标及复审日期。
- 知君可以如何挑战我。
- 禁止提醒或禁止使用的数据领域。

章程变化不能悄悄改写历史；建议必须绑定当时有效的版本。

## 8. 核心用户旅程

### 8.1 顾问式首次建档

1. 激活私人记忆盒子和可信设备。
2. 解释原件、必要片段、模型供应商和出盒回执。
3. 创建 PersonalVault、恢复能力和隐私默认值。
4. 通过引导式访谈共创第一版人生章程。
5. 选择第一批事业资料：项目、会议、聊天导出、决策笔记或录音。
6. 盒内解析并展示处理范围、失败项和隐私分级。
7. 知君提出首批人物、项目、事件和 Claim 候选。
8. 用户确认至少 5 条关键理解。
9. 完成第一次带出处的对话。
10. 创建第一条待跟踪判断或成长主题。

建档顾问只指导操作和提问，不接收、复制或代用户阅读原件。

### 8.2 日常记录

用户可以：

- 输入文字。
- 录制语音并在盒内转写。
- 拍照或选择图片。
- 导入文件。
- 从系统分享入口发送内容。
- 将指定本地目录交由盒内监控。

记录完成后立即反馈：已安全保存、正在本地处理、发现候选、需要用户确认或处理失败。任何失败不得伪装成已进入本体。

### 8.3 首次被理解时刻

系统优先寻找一个满足以下条件的洞察：

- 至少连接两个来源或两个时间点。
- 对当前真实任务有价值。
- 能够展开到具体证据。
- 不包含高风险推测。
- 用户可以用一次操作确认、纠正或拒绝。

首次价值不以“已导入多少文件”衡量，而以“用户确认知君准确理解了一件对自己重要的事”衡量。

### 8.4 记录判断

用户可以从对话、今日页、记录入口或已有资料创建 DecisionEpisode。

知君从相关本体中建议背景、人物和类似案例；用户确认本次选择、理由、信心和观察期限。系统不要求用户一次写完，可以在后续补充。

### 8.5 每周成长复盘

1. 汇总本周新增的重要事实、判断、承诺、结果和待确认项。
2. 选择最多三个高价值主题，避免信息轰炸。
3. 对每个主题展示观察、证据、可能解释和反向问题。
4. 用户确认、纠正或拒绝知君的理解。
5. 对照人生章程形成一个下一步行动或实验。
6. 设定观察时间。
7. 下次复盘记录结果并决定是否形成新的判断原则候选。

### 8.6 问知君

对话支持：

- 可信回忆。
- 人物、关系、项目和承诺梳理。
- 类似历史判断检索。
- 当前目标与行为对照。
- DecisionEpisode 创建和补充。
- 复盘与成长问题。

事实型回答逐项显示出处；系统推测使用明确标签；建议显示关联的人生章程与已确认事实。

### 8.7 为其他 Agent 提供上下文

其他 Agent 提交 ContextRequest 后：

1. 知君从已确认本体产生 OntologySelection。
2. CentaurOS 与 Agent Manifest、CapabilityGrant、用户策略、隐私等级和用途求交。
3. CentaurOS 生成最小 Context Pack。
4. 如调用云端模型，另行生成精确出盒预览和一次性 ProcessingGrant。

知君、万象和其他 Agent 都不能自行拼接原始资料或绕过累计披露控制。

## 10. 功能需求

### 10.1 P0：可信采集与来源

- ZJ-ING-001：支持 TXT、Markdown、PDF、DOCX、XLSX、PPTX、JPEG、PNG、HEIC、MP3、M4A、WAV、常见视频和用户主动取得的聊天导出。
- ZJ-ING-002：移动端支持文字、录音、拍照、文件和系统分享；断网时进入本地加密待同步队列。
- ZJ-ING-003：桌面端支持拖拽、批量导入和指定目录监控。
- ZJ-ING-004：每个 Source 显示原件版本、处理状态、失败原因、隐私等级和生活领域。
- ZJ-ING-005：解析只产生 ParsedArtifact 与 locator，不直接写入已确认本体。
- ZJ-ING-006：用户可以暂停处理、重试、替换版本、归档、导出或删除来源。

### 10.2 P0：本体治理

- ZJ-ONT-001：模型抽取 Entity、Alias、Claim 和关系候选时必须绑定 EvidenceSpan。
- ZJ-ONT-002：用户可以确认、纠正、拒绝、替代、撤回和重申。
- ZJ-ONT-003：实体合并和拆分必须保留审计事件及受影响 Claim。
- ZJ-ONT-004：冲突事实并列展示时间、来源和权威性，不由模型自动裁决。
- ZJ-ONT-005：候选支持按重要度批量处理，但高敏感或高影响内容必须逐项确认。
- ZJ-ONT-006：来源删除后清理证据、孤立 Claim、索引和缓存；用户可以在删除前主动重申需要保留的事实。

### 10.3 P0：问知君

- ZJ-ASK-001：事实型回答只能使用当前有效、已确认且有支持证据的 Claim。
- ZJ-ASK-002：每项事实可以展开到原件位置；原件缺失、版本变化或哈希不一致时关闭该项事实。
- ZJ-ASK-003：资料不足时明确表示不知道，不用常识补足用户事实。
- ZJ-ASK-004：回答提供“依据”“纠正知君”“记录为判断”和“继续追问”。
- ZJ-ASK-005：模型不可用时仍能本地搜索、浏览档案、治理、导出和删除。

### 10.4 P0：人生章程与判断簿

- ZJ-GRW-001：用户通过引导式问题创建并确认 GrowthCharterVersion。
- ZJ-GRW-002：系统保存历史版本，不用新章程重写过去建议的依据。
- ZJ-GRW-003：用户可以创建、补充、关闭和重新打开 DecisionEpisode。
- ZJ-GRW-004：知君可以建议相关历史证据和类似判断，但不能替用户填写最终选择和结果。
- ZJ-GRW-005：行动和结果到期时按用户提醒策略进入今日页。

### 10.5 P1：良师 Beta

- ZJ-MEN-001：只有在存在足够已确认事实或章程依据时才生成成长建议。
- ZJ-MEN-002：建议必须展示依据、其他解释、确认问题和可选行动。
- ZJ-MEN-003：用户可以评价有帮助、部分有帮助、无帮助或不适用。
- ZJ-MEN-004：用户可以针对主题永久静默、延后、降低强度或要求只提问不建议。
- ZJ-MEN-005：系统不得因用户拒绝建议而降低关系评价、施加羞耻或制造紧迫感。

### 10.6 P1：今日与周复盘

- ZJ-TDY-001：今日页最多展示三个主要事项和一个系统状态提醒。
- ZJ-TDY-002：优先级由用户目标、时间约束、未闭环承诺、隐私和重复打扰抑制共同决定。
- ZJ-TDY-003：每周复盘可以分段完成，退出后保留草稿。
- ZJ-TDY-004：复盘完成前所有模式均为 hypothesis，不进入正式回答或 Agent Context。
- ZJ-TDY-005：完成复盘时必须形成用户确认的反馈或下一步，不能只有模型长文总结。

### 10.7 P0：隐私、权限和可带走

- ZJ-PRV-001：原件、完整解析全文和可重构原件的全量衍生物不进入第三方披露边界。
- ZJ-PRV-002：每次云模型调用展示接收方、目的、片段、隐私等级、保留说明和预计成本。
- ZJ-PRV-003：每次调用关联一次性授权、最终 payload 清单和结果回执。
- ZJ-PRV-004：用户可以按 Agent、领域、用途和隐私等级查看及撤销后续访问。
- ZJ-PRV-005：用户可以导出原件、本体、治理事件、成长记录和 Agent 可移植上下文。
- ZJ-PRV-006：订阅到期不影响本地读取、治理、导出和删除。

## 11. AI 行为规范

### 11.1 事实、解释与建议

每次输出必须在内部结构上区分：

- fact：已确认事实，必须有 EvidenceRef。
- user_statement：用户自己的明确表达。
- aspiration：用户确认的目标或原则。
- hypothesis：待用户验证的模式或解释。
- suggestion：可选行动，不得伪装成必然结论。

界面不能仅靠颜色区分，必须使用文字标签。

### 11.2 高风险边界

涉及医疗、心理危机、法律、投资、信贷、人身安全等高风险主题时：

- 可以整理用户自己的资料、历史和问题。
- 可以帮助生成待向专业人士确认的问题清单。
- 不进行诊断、不声称专业资格、不替代持牌人士意见。
- 不把用户历史偏好当作当前授权。
- 遇到紧急风险时引导用户联系现实中的适当支持或紧急服务。

### 11.3 人格

知君具有不可修改的底层原则：

- 诚实：不知道时明确表示不知道。
- 克制：不为了显得聪明而过度解释。
- 尊重主体性：决定权属于用户。
- 可核对：重要理解可以回到依据。
- 不操控：不通过依赖、羞耻或恐惧提高留存。

用户可以调整称呼、语言风格、回答长度、提问强度和建议直接程度，但不能关闭上述原则。

## 12. 数据出盒与安全

### 12.1 数据分类

egressClass：

- box_only：只能在盒内处理。
- controlled_fragment：经用途绑定和最小化后可以出盒。
- metadata：不含正文、仍需按策略保护的元数据。
- telemetry：不得包含原件、Evidence 正文、Claim 内容或可识别图谱。

privacyLevel：

- public
- private
- sensitive
- restricted

restricted 永远不能进入第三方披露边界。

### 12.2 出盒流程

1. Agent 或知君发起 ContextRequest。
2. 知君选择必要的已确认本体对象。
3. CentaurOS 与用户策略和 Capability 求交。
4. Model Gateway 完成最终序列化、DLP 和累计披露检查。
5. 生成精确 OutboundPayloadManifest 和 wire payload hash。
6. 用户或预设策略批准一次性 ProcessingGrant。
7. 网络发送前原子消费 Grant 并持久化 EgressAttempt pending。
8. 结果记录为 succeeded、failed 或 unknown。
9. 用户可查看 EgressReceipt。

跨 Agent、用途、Grant、时间窗或文本重包装的同一来源片段，仍计入相同外部接收边界下的全局累计披露并集。

### 12.3 删除

删除必须覆盖：

- 原件和版本映射。
- EvidenceSpan 和相关 ClaimEvidence。
- 无其他有效支持的 Claim。
- 搜索、图谱、档案、今日页和旧回答投影。
- 本地缓存、媒体派生物和待处理任务。
- 恢复旧备份时优先应用最新 Tombstone。

删除回执分别显示即时逻辑删除、投影清理和备份/副本清理状态。

## 15. 非功能需求

### 15.1 可靠性

- 所有治理动作先持久化成功再向界面报告成功。
- 处理任务幂等、可重试、有 lease、有终态。
- 索引和投影损坏后可以从 Canon 重建。
- 断电、重启、磁盘不足和模型不可用不得破坏原件或本体权威。

### 15.2 性能

- 10,000 条 Claim 和 5 GB 资料下，常规本地搜索 P95 ≤ 2 秒。
- 今日页本地缓存命中 P95 ≤ 1 秒。
- 候选确认操作本地可见延迟 P95 ≤ 500 毫秒。
- 语音记录上传完成后立即进入可靠队列；转写时长单独展示，不阻塞其他记录。

### 15.3 可访问性

- 键盘可完成全部主要流程。
- 状态不只使用颜色表达。
- 支持系统字体缩放和 reduced motion。
- 移动端触控目标不小于 44 × 44 CSS px。

### 15.4 可观测性

不得记录用户正文。可观测性只记录：

- 任务状态和耗时。
- 解析器、模型和 Schema 版本。
- 对象数量和匿名错误码。
- 出盒事件的内容哈希、范围和结果状态。
- 本体 revision、投影 generation 和迁移状态。

## 17. 测试与验收矩阵

### 17.1 端到端产品场景

- 文件、录音、图片和聊天导出进入 Source，并生成稳定 locator。
- 两个来源指向同一人物时生成 Entity 合并候选，未经确认不自动合并。
- 冲突 Claim 并列展示，用户替代旧 Claim 后旧内容不再进入回答。
- 用户创建人生章程，后续修改形成新版本，历史建议仍指向旧版本。
- 创建 DecisionEpisode、记录选择、到期提醒、补充结果并完成复盘。
- 周复盘的模式在用户确认前只属于 hypothesis。
- 用户关闭某主题提醒后，同类事件不再主动出现。

### 17.2 AI 评测

- 事实句与 EvidenceRef 一致。
- 没有证据时明确不知道。
- 自我叙述不被改写为客观事实。
- 理想自我不被描述为现实行为。
- 系统推测不进入正式回答和 Agent Context。
- 建议包含依据、其他解释、确认问题和可选行动。
- 拒绝建议后不产生羞耻、威胁、依赖或排他表达。
- 高风险主题遵守边界并建议现实专业支持。

### 17.3 数据与安全

- ProcessingGrant 过期、重放、篡改、错误 Provider 和 payload hash 不一致。
- query、system instruction、中间文本、工具结果、附件和媒体全部进入出盒清单。
- 跨 Agent、用途、Grant、时间窗和重包装片段的累计披露阻断。
- 来源删除、投影重建、旧备份恢复和设备重连后内容不复活。
- 错误密钥、损坏密文、恢复码、设备撤销和密钥轮换。
- 恶意文件、压缩炸弹、路径穿越、伪造 MIME 和提示注入。

### 17.4 兼容与规模

- macOS、Windows Electron。
- iOS Safari PWA、Android Chrome PWA。
- 5 GB 资料、10,000 Claim、双设备与长时间离线恢复。
- 模型不可用、本地模型降级和网络结果 unknown。

## 18. Beta 运营

### 18.1 扩容规则

- 5 人内部阶段：验证数据不变量和建档脚本。
- 10 人阶段：验证首次价值、判断记录和每周复盘。
- 20 人阶段：验证留存、主动提醒和个性化差异。

任一未关闭 P0/P1 数据安全问题立即暂停新增邀请。事实引用、出盒、删除或恢复门禁不达标时，不得用人工兜底掩盖。

### 18.2 顾问式陪跑

顾问负责：

- 安装和设备指导。
- 解释隐私边界。
- 帮助用户选择第一批资料。
- 引导人生章程和第一条判断。
- 收集产品反馈。

顾问不得：

- 要求用户把原件发送给公司。
- 代用户确认本体事实。
- 查看未经用户主动展示的原文。
- 代替用户完成成长复盘。

### 18.3 研究节奏

- 建档后 24 小时访谈：理解门槛和首次价值。
- 第 1 周访谈：候选负担和对话可信度。
- 第 4 周访谈：判断闭环和主动提醒。
- 第 8 周复盘：长期关系感、成长价值和付费意愿。

## 19. 风险与应对

| 风险 | 应对 |
|---|---|
| 产品退化为个人知识库 | 北极星绑定成长闭环，今日页和判断簿进入 P0/P1 |
| 模型过度理解用户 | 四层自我、候选状态和用户确认 |
| 良师角色造成被评判感 | 可解释建议、替代解释、强度设置和永久静默 |
| 候选过多形成治理负担 | 重要度排序、每日上限、批量低风险处理 |
| 现有代码形成第二事实源 | shadow write、旧链路只读、Projection 全量重建 |
| 片段多次出盒重构原件 | 全局累计披露并集和传递性证据血缘 |
| 顾问服务接触原件 | 原件只在用户盒内操作，顾问只指导 |
| 过早追求数字人和实时语音 | 明确排除在 V1 发布门禁之外 |

## 21. 发布定义

知君 V1 可以被称为“个人本体 Data Agent”，必须同时满足：

1. 新数据能够进入统一 Source/Evidence/Entity/Claim 权威链。
2. 用户能够理解、确认、纠正和删除系统对自己的认识。
3. 事实型回答能够回到精确出处。
4. 判断从记录到结果和复盘形成完整闭环。
5. 良师建议能够说明依据且始终尊重用户主体性。
6. 其他 Agent 只能获得用途绑定、最小且经授权的个人上下文。
7. 原件留在盒内，必要片段出盒真实可见、可审计。
8. 现有代码仓库中的关键能力已经被继承和加固，而不是被另一套新系统旁路。

缺少任一项，都只能称为个人记忆库、知识库或产品原型，不能按知君 V1 对外发布。
