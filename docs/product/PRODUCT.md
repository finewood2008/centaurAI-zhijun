# 知君产品定义

知君是一个通过长期对话逐渐理解用户、并把这份理解交给用户核对和掌管的思考伙伴。它可以记住人与事、原则、判断和复盘，但不会替用户作决定，也不会把模型推测伪装成事实。

## 核心原则

- 对话优先：资料导入用于补充证据，不是使用产品的门槛。
- 用户拥有最终解释权：用户可以确认、修改、撤回或拒绝任何理解。
- 来源可核对：区分用户原话、资料观察、系统推测和理想方向。
- 建议比结论谦逊：说明依据、不确定性和其他可能解释。
- 陪伴不制造依赖：不声称情感、意识或权威，不用羞耻和恐惧促活。
- 本地优先：原件和受限资料留在设备内；在线调用只使用获得授权的必要内容。

## 主要入口

| 入口 | 作用 |
|---|---|
| 今日来信 | 汇总值得关注的变化、事项和下一步 |
| 对话 | 持续交流、形成理解、商量判断并查看回复出处 |
| 照见 | 回看跨时间的观察、原话依据与自己的补充修正 |
| 我的本体 | 核对知君对用户的理解及其来源、信任状态和可带走范围 |
| 判断 | 管理人生章程、判断、结果和复盘 |
| 资料与边界 | 管理资料、模型、授权、导出和清理 |

## 记忆和信任

知君区分对话记录、尚待核对的工作理解和用户已经确认的理解。系统推测必须保持可见的不确定性；撤回或纠正的内容不能悄悄回流。资料来源、会话历史和个人理解是否可供在线模型使用，分别受版本、用途和授权约束。

## 模型行为

本地模型与在线模型是用户可见的明确选择。在线失败不自动降级到本地；系统生成的话头可以有一次性本地限制，但用户显式选择在线后应以用户选择为准。每条实际回复的执行通道以保存的回执为准，模型在正文中自报名称不构成证据。

盒端本地推理由 CentaurOS 管理。当前产品要求 NPU-only 时，CPU 禁用和无 CPU fallback 必须在 CentaurOS 运行时落实；桌面应用只负责路由选择、授权和结果展示。

## 不做什么

- 不替代医疗、心理、法律、投资或人身安全方面的专业判断。
- 不代表用户发送消息、付款、签署文件或作出外部承诺。
- 不把向量索引、摘要、知识卡或模型输出当作第二事实源。
- 不在未授权时外发原件、受限历史或个人理解。

## V3 自我照见

先让用户感到被准确记住，再将不同时间的经历联系起来，提出可核对的观察。第一次体验优先关注具体情境中的取舍与变化；用户的解释和纠正会影响后续对话。允许知君暂时没有发现，不以照见数量或用户同意率衡量价值。

照见通过对话卡片自然出现，提供原话依据与像我、看情况、不像我、再观察四种反馈，也可用自己的话补充。主导航与首页提供回看入口。照见始终保留推断属性，用户认可不自动将其升级为本体事实；不同意是一种正常、有价值的校准。
