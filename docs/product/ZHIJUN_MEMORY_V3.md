# 知君记忆系统 V3 · 设计文档

版本：2026-09-17 · 基线代码 `98c2331` · 状态：第一阶段实施中（分支 `redesign/memory-v3`）

## 1. 问题与目标

产品负责人的判断：目前的对话不能有效引导用户进行深度对话，对用户的理解也不够深；用户感觉不到「知君非常了解我」。

代码层面的根因（逐条对应到实现）：

| 现象 | 根因 |
|---|---|
| 知君答话像第一次见面 | 常开画像只有「我是谁」分区 ≤4 条 / 600 字；原则、做法、方向、人、事项全靠本轮词面命中才进提示词 |
| 相关的过去想不起来 | 召回唯一闸门是词面相似度 0.12，没有时间、重申、重要性权重 |
| 换一段对话就忘了上次聊到哪 | 跨对话没有结构化对象；主题与待办生成了却只当文本参与竞争；提醒从不进提示词 |
| 说过的话总要再点一次「对」 | 主路径下理解永不自动确认，重复命中不追加证据、不刷新重申；整合器的晋升 / 衰减 / 推迟被跳过。记忆只进不熟 |
| 「别老问我问题」说了没用 | 「怎么对我说话」的偏好没有捕获与应用回路 |
| 知君不会问出好问题 | 它不知道自己不知道什么：缺口、过期、张力、未了事项都不通往下一句 |
| 「第一次被理解」的时刻没了 | 第一次观察与照见两条任务线没有调用方 |

目标：用户在第二次、第三次打开知君时，能从第一句话感到「它记得我、它知道我在忙什么、它会问到点上」；并且用户能看见、能改、能撤回知君带着的每一条认识。

## 2. 借鉴 Claude 的记忆设计

Claude 的记忆分三层可参考的做法（本机可读的 API 与托管代理参考，加上 Claude Code 的自动记忆规则）：

| Claude 的做法 | 知君 V3 的对应 |
|---|---|
| 一事一文件，带 frontmatter：`description` 用于判断召回相关性，`type` 分 user / feedback / project / reference | claim 仍是记忆单位；新增 `why_it_matters`（为何重要）参与召回；新增「相处方式」记忆类型（对应 feedback） |
| 每次会话都加载的索引（MEMORY.md），逐条记忆按相关性再召回 | **核心画像**：确定性生成、常驻提示词的一页纸；逐条召回在其之上 |
| feedback 记忆必须带 Why 与 How to apply | 相处方式记忆带 `why_it_matters` 与 `how_to_apply`，无条件注入 |
| 更新已有而不重复、删除错的、不存可推导的、相对日期转绝对 | 重复命中追加证据并重申；撤回进墓碑永不回流；事件性内容不入长期；日期已转 ISO |
| 召回的记忆是背景不是指令；引用前先核实仍成立 | 提示词里标为参考数据；过期理解由求知引擎触发自然核对 |
| 记忆库每次改动留不可变版本，可回滚、可脱敏，主机侧可审核修正 | review_events 已是版本流；一键撤回；核对面板 |
| claude.ai：用户可见、可编辑的记忆摘要；「你记得我什么」 | 「知君对我的理解」= 后端核心画像原文，逐行可改；自述意图从画像作答 |

不照搬的部分：Claude 让模型直接读写记忆目录；知君坚持**盒子是本体唯一写入者**，模型只产出带引用的候选，信任状态、衰减、墓碑、投影全部由本地代码决定。

## 3. 设计

### M0 核心画像

- scope 级、确定性生成、不调模型。缓存于本体 meta（`zhijun_core_profile_v1[:scope]`），以来源哈希判断是否重建；哈希不含当天日期，文本稳定利于提示缓存。
- 分区与上限：我是谁 4 · 重要的人 3 · 正在做的事与承诺（活跃事项 2 + 承诺按到期 3 + 在做 2）· 原则 4 · 做法 3 · 方向 3 · 近期脉络（最近 3 段对话的主题各 3 + 待办 4 + 7 天内到期判断 2）。
- 每行带来源标签与日期：`- [你告诉我的·2026-08-30] 我负责公司的产品研发`。
- 取材规则：只取已确认、未被挑战、未推迟、非仅当时、未过期、非受限；外发时再去掉敏感与本地专用。排序按证据来源数、最近重申时间。
- 预算：外部模型 1200 字，本地 600 字；超出按 近期脉络 → 方向 → 做法 → 人 → 原则 → 事 → 我是谁 丢弃，每段至少留一行。
- 注入位置：人格之后、章程与本轮证据之前；画像里的理解不再重复进入本轮证据。
- 重建时机：抽取有新增 / 晋升 / 重申后、对话摘要后、用户核对后、手写补一条后、记结果后、整合后。
- 接口：`GET /api/mindos/ontology/core-profile` 返回知君实际带着的这一页。

### M1 召回权重与纠正块

- 在 0.12 词面闸门之后加有界加成（合计不超过 0.12）：证据来源数、多处提到、有「为何重要」、30 / 90 天内重申；超过一年且单来源轻微降权。
- 商量与深聊时，人与原则两个分区放宽门槛各取一条。
- 主路径恢复「用户已纠正、不得再复述或暗示的旧理解」块（撤回与被替代的理解，词面相关时列出，仅作禁止复述提示）。

### M2 记忆成熟

- 用户亲口说的、原话可精确引用、第一人称、置信 ≥ 0.8、长期范围、未被降级、非辅助表达的自述，直接记为「你告诉我的」（已确认）；推测与资料观察仍需点头。「仅在我要求时整理」模式下仍只出待确认。
- 重复说到已有理解：追加证据并刷新重申；待确认理解被本人再次亲口说到即确认。
- 整合器的晋升（多来源置顶）、衰减（被挑战超 30 天撤回）、推迟（单来源超 60 天推迟）在生产路径生效，仍只作用于待确认理解。
- 撤回：「这段对话留下的」卡对直接记下的理解提供一键撤回，撤回进墓碑。

### M3 相处方式记忆（第二阶段）

- 识别用户对知君行为的要求（「别老问我问题」「多挑战我」「说重点」），存为 `ways / wants_zhijun_to`，自述即确认，带 `why_it_matters` 与 `how_to_apply`。
- 无条件注入「用户希望的相处方式」块，优先于默认对话方式，不越过底层原则。
- 设置 → 关系设置 中可看、可撤、可补。

### M4 求知引擎

知君要知道自己不知道什么。`inquiry.targets` 产出按优先级排序的目标，每条配一句温和的问句：

| 类型 | 来源 | 问句示例 |
|---|---|---|
| 缺口 | 某分区已确认理解不足 2 条 | 「平时你的职业或岗位是什么？」 |
| 过期 | 已确认、单来源、超 60 天未重申 | 「上次你说「…」，现在还是这样吗？」 |
| 张力 | 待裁决的矛盾 | 「「A」是你确认过的原则，而最近「B」，是原则变了还是这次特殊？」 |
| 未了结 | 近 14 天的待办、到期判断、到期承诺 | 「上次你说要「…」，后来怎么样了？」 |
| 待点头 | 多处提到的待确认理解 | 「我印象里…，对吗？」 |
| 建档话题 | 未聊完的建档主题 | 建档脚本的下一题 |

约束：静默领域过滤；章程关闭主动时只留缺口与待点头；同一目标 7 天内不重复；一轮最多一问，深聊、商量、倾诉、用户本句是问句时不问。用于提示词、开场白、今日来信。

### M5 主动开口

新对话创建时写一条模板开场（不调模型）：有近期脉络与目标时「上次我们聊到「…」。{问句}」；只有目标时直接问；无画像或章程关闭主动时用最轻的一句、不带问句。开场消息带路由来源引用，在线且未授权时按受保护历史处理，不阻塞对话。

### M6 透明可编辑

- 本体页「摘要」视图渲染后端核心画像原文，逐行可「还是这样 / 不再这样了 / 详情」；顶部说明「知君每次回答都带着这一页」。
- 「你记得我什么」意图先按画像逐段作答，标明未纳入的部分。

### M7 提醒进目录（第二阶段）

新增目录项：提醒今日列表、扫描、划掉、静默；今日来信挂回提醒条；盒端已有每小时扫描。

### M8 知君的主动性（2026-09-17 负责人补充：今日来信一天一次太少，知君应更像一个了解你、会主动找你聊的人）

像人一样主动，意味着四件事：有理由才找你（每次都能说出「为何现在」）；有节律（一天不止一次但不密集，知道你什么时候在、什么时候别打扰，被冷落几次就退一步）；记得自己说过什么（不重复问，你没回它记着，下次接上）；有自己的关注点（在跟进你的承诺、判断、事项，会主动说）。边界：不假装有情绪或自己的生活，人格化体现在注意力、记忆、主动和分寸。

**触发源**：时间性（承诺到期、判断回访日、事项下一步、周回顾）；事件性（资料处理完、整合器发现张力、多处提到等你点头）；未了结（上次聊到一半的事过了几天）；关系性（认识第 7 / 30 / 100 天、多日没聊的轻问候，可关）；求知性（认识初期每天补一个还不了解的分区）。

**形态阶梯**：今日来信（一天一封，当天的开场）→ **知君发起的对话**（盒端每小时扫描，从触发源里挑最多一条，直接创建一段对话并先说一句，带「为何现在」；出现在对话列表方印「知君发起」与今日页「知君想和你聊」；回不回都行）→ 桌面通知（应用在后台时一行通知，默认关，第二阶段，需动 Electron 壳）。

**节律**（关系设置可调）：每天上限默认 2 次；两次至少间隔 4 小时；安静时段默认 22:00 到 08:00；你刚活跃的两小时内不找你；连续 3 次没回应退到一周一次；任何主动消息上都有「先别找我三天」；章程静默领域与「关闭主动」照旧；同一件事 7 天内不重复。

**实现**：任务 `proactive_scan` 复用提醒扫描的调度（盒端 `domain.tick` 每小时）；策略并入现有提醒策略接口（`proactive` 对象），不加目录项；会话带 `initiated` 元数据，首条消息 `meta.kind = zhijun_initiated`；今日接口带 `initiated` 列表。

### 人格

深度阶梯：接住 → 具体化 → 连过去 → 一个好问题 → 看法 → 留白；每轮只推一两步，倾诉时停在前两步。画像使用：相关时自然地说「上次你说…」并带来源标签，不整段复述、不列清单；与本轮所说冲突时以本轮为准并轻声核对。仍不得自称已保存。

## 4. 信任与隐私不变量

- 四个来源标签、五条不可关闭原则、不催不哄、不自称已记录：不变。
- 墓碑（撤回、被替代）永不回流到画像、证据与开场白。
- 外发过滤：敏感、受限、本地专用不出设备；画像不写入 USER.md 投影；核心画像接口仅本机可读。
- 授权与路由不变量不变：预览、授权、逐块出口检查。
- 「仅在我要求时整理」模式语义不变。

## 5. 度量

- 第二次对话的开场被接话率。
- 回复引用过去时用户说「对」的比例；用户纠正率。
- 核心画像分区覆盖度（六个分区各 ≥ 2 条已确认）。
- 求知引擎的问句被回答率。
- 反指标：一轮多问、用户说「别问了」的次数、撤回率。

## 6. 分阶段

- 第一阶段：M0、M1、M2、M4、M5、M6、人格、文档（本分支）。
- 第二阶段：M3、M7、跨时间观察（复活照见任务，入队改在摘要之后）、学习片段进回看。
- 第三阶段：行为数据导入与一致化名脱敏（需要 Data Engine 配合）。
