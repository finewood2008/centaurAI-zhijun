# 对话到本体抽取修复计划（2026-09-15）

## 现场依据

公司盒子最近的 `extract_turn` 有两类阻断：任务返回 `paused/consent_required`，缺失来源仅为章程；另一些任务在登记阶段失败，错误为 `WORKSPACE_WORKER_PROOF_INVALID`。前者尚未调用抽取模型，后者甚至尚未进入执行队列。任务外层 `done` 不等于生成了候选。

## 范围与依赖

- 主线：`charter_policy.py`、`extract.py`，将事实抽取与章程正文外发解耦，保留本地控制、版本快照及保存前复核。
- 多轮：独立自述不携带上一条 AI 回答；确需上一问的答案保留其来源授权，不保留正文却丢弃来源。
- 并行：专门核查 Worker 登记凭证与安全失败边界；测试代理只修改测试文件。
- 不改变用户的章程外发授权，不将候选自动确认为正式本体，不自动重放历史对话。
- 保留已经部署的容量回收及 memory index 422 修复；盒端升级必须备份、核对版本和健康状态。

## 验收

1. 已发布章程、默认授权不含章程时，独立自述生成 `working` 候选，抽取请求没有章程正文或引用。
2. 前一条 AI 消息含章程来源时，独立自述仍正常；依赖上一问的简短答案不得绕过来源授权。
3. `memory_manual`、`local_only`、中途章程变化仍可阻止不允许的抽取或写入。
4. 后台登记失败按真实边界处理，不盲目重试可能已执行的操作，不放宽签名验证。
5. 回归现有记忆、章程与 Worker 合约测试，检查代码差异；部署后验证实际文件哈希、服务健康与数据保留。

## 实现和验证

`extract_turn` 不再注入章程正文，但保留本地章程控制和版本快照。独立自述不携带上一条 AI 内容及其来源；对明确槽位问题的依赖性回答继续完整校验来源授权。没有放宽默认授权，也没有将 `working` 候选直接确认为正式记录。

DE 内部能力入口仅在派发前验签失败时输出白名单精确错误码。只有 `401 + WORKER_PROOF_EXPIRED + rejectedBeforeDispatch=true` 的 `domain.background.register` 会重新签名一次；保持原请求体、原业务来源，更新 nonce，TTL 仍为 5 秒。签名错误、重放、未知错误、断连、超时、500、缺少标记、二次过期均不触发不确定重放。历史两次登记错误没有细分日志，**不能断言其原因已经证实为过期**；本次新增的无敏感内容错误码日志用于进一步确认。
