# 情境校准版 · 2026-09-04

本版把“记住与校准”向“用新经历修正理解”推进一步。复用判断簿、会话和 ontology.db，
不训练独立的个人模型，不建立第二套画像，也不宣称能够还原潜意识。

## 用户入口

确认判断后，会话右侧出现可折叠的“用这次经历校准理解”。今日来信中的回访/复盘也进入同一对话。

1. 从与判断相关、已经确认的理解中选择一条。
2. **事情发生前**写下情境、可观察的预期、可能挑战预期的结果。可以请本地 AI 草拟，再自己修改。
3. 明确确认后冻结观察。没有事前观察的旧判断只做普通复盘，不能事后补成预测。
4. 原有“记下结果”收到真实结果后，选择吻合/不同/部分吻合/无法判断，并记录原因与修订措辞。
5. “保存对照”不改写本体。可保留旧理解、先不判断，或明确确认并修订这一条理解。

模型预期和用户在判断中填写的“希望的结果”分开；对照结果和自我贴合度分开。
本版最多展示六条相关候选；没有合适的候选时不要求用户新增标签。
自动草拟仍需用户审阅，不能作为模型预测能力已经达标的证据。

## 数据与事务

- 增量迁移：`claims.context_json`（可空）和 `learning_episodes` 表；不改写历史 Claim。
- episode 按判断唯一，保存原理解/校准/证据版本快照、预期、时间、对照提议和最终处理结果。
- 预期只允许在判断 `open` 时写入；已有同内容重试返回原记录，不允许覆盖预期。
  此门禁验证的是“早于结果记录”，真实事件是否已经发生仍需用户诚实标注，不能等同于研究级盲测。
- 对照必须有实际结果引用；用户明确应用时，经唯一 Claim `transition(partial)` 入口，
  在**同一 SQLite 事务**内替代旧理解并完成 episode。旧理解、证据和审计历史保留。
- 校准修订、内容、证据或提议有新版本时旧请求不能覆盖。相同最终请求重试不会重复创建 Claim。
- 新措辞没有自动继承旧的贴合度；情境/阶段/愿望/长期认同独立标注。
- 原有复盘经验现在是 `ways/hypothesis/context_only` 候选，不因一次复盘成为终身原则或愿望。
  不再按相似措辞合并两次复盘并提高晋升标志。
- 抽取的 `scope_hint=unknown` 不再映射为长期倾向。既有记录不批量重新分类。
- 矛盾整理先区分情境、时间范围和愿望，不把条件不同直接当矛盾或等价。

## 本地处理和来源限制

此首版的经历校准**仅本机**，尚未开放外部服务授权入口。模型不可用/繁忙时可手动完成；
不静默使用外部模型。调用上限55秒，页面65秒超时后可刷新检查结果。

`SourcePolicy` 解析 Claim → review/decision → conversation/material 祖先；缺失祖先保守处理。
它也拦截旧版已存在的“本地决策 → 普通 private 复盘候选”泄露路径，不只保护新记录。
新修订附带本地来源标记。即使以后打开通用导出开关，也不能绕开来源限制。

共用此检查的出口：普通对话（已确认/候选/撤回记录）、历史判断、全局整理、首页 AI 来信、
Context Pack、USER.md。完整本地画像仍可查看；本地回复保留 `localOnlyDerived`，
让后续历史、摘要和普通后台任务继续受限制。原有文件与贴合度授权不被当成此次校准授权。
首页预填话头也带仅本地标志，避免复制到新会话后丢失派生来源。

## 验证与边界

- `backend/tests/test_context_learning.py`：冻结、重试、重启恢复、显式修订、并发版本、
  本地模型不可用、来源失效、设备作用域、历史复盘泄露、后台摘要/整理/首页与导出。
- 合成案例覆盖工作安排、认同的原则、尚未实现的愿望和不同情境；结果在预期冻结后才提供。
- `frontend/mindos-web/tests/context-learning.e2e.mjs` + 隔离 fixture：真实 Vue/API 流程、
  刷新、模型失败后手动填写、AI 草稿不保存、修订确认及390px宽度。
- 真实 `qwen3.5:9b` 仅对隔离合成记录进行事前/事后调用，不使用真实用户记录。

这些是功能与隐私回归测试，**不是个人行为预测准确率评估**。本版没有自动跨年传记、
跨情境模式发现、六类认知内容的完整结构化提取，也没有用平均贴合分或核心圈点数衡量成长。
后续需要积累用户真实愿意反馈的独立经历，以时间留出的案例检查预测与修订是否确实有帮助。

回退代码时新表/可空列可以保留；不要用备份覆盖上线后新增的真实记录。
