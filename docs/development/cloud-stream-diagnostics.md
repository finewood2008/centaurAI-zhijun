# 云端对话空正文：诊断工具与实测记录

## 范围

知君桌面报 `MODEL_RESPONSE_EMPTY`（“模型没有返回可显示的正文”）时，不能仅凭供应商调用/计费记录判断模型正文是否返回。

工具位于 `scripts/diagnose_cloud_stream.py`，由知君维护；不修改 Data Engine 代码，不重启服务，不修改供应商、外发授权或默认模型。诊断只验证供应商传输和盒端流解析，不代替真实 Gateway 租约、材料授权、桌面端到端验收。

## 公司盒子实测：2026-09-13

目标 `192.168.0.7`，容器 `zhijun-integration-0907`。只读确认 18:55 对话记录为 online/openai、`deepseek-v4-flash`、状态 error、内容对应 `MODEL_RESPONSE_EMPTY`，用量未保存。

实际运行的 DE `model_stream.py` SHA-256：

`034de2ab863a532a990458f2e7336e1e072f3c89bf1aedb9229eaa3d83783917`

以下是三个独立、串行、固定合成内容的请求，均使用现有工作区供应商配置，`effort=low`、`temperature=0`。没有发送真实聊天、材料、章程或用户标识；未自动重试。

| 合成问题 | max_tokens | 首个 SSE 帧 | 首段正文 | 总耗时 | 推理字符 | 正文字符 | finish_reason |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 只回答“连接测试成功” | 1024 | 0.354 秒 | 1.087 秒 | 1.090 秒 | 478 | 6 | stop |
| 用约 200 汉字讨论如何定义成功 | 1024 | 0.372 秒 | 4.672 秒 | 5.019 秒 | 1532 | 188 | length |
| 同上 | 4096 | 0.365 秒 | 5.586 秒 | 6.004 秒 | 1563 | 219 | stop |

三次均为 HTTP 200 / `text/event-stream`、Chat Completions 增量；DE 转发的正文字符数与诊断观测一致，没有观察到最终快照有正文而解析器漏读。推理字符数不是 token 数；上游流在当前解析器停止读取前没有给出 usage，因此不能据 DE 的默认零用量认定零消耗，也不能把 SSE 帧数当 token 数。

### 已确认

- `effort=low` 在这个实际通道上仍会产生推理内容，并不等于关闭思考。
- 1024 输出预算的测试触及 `length`；同题 4096 预算正常 `stop`。这验证了该通道存在输出预算不足的风险；仅延长超时不解决长度截断。
- 当前解析器能读出这些请求的正文增量。首帧较快，但正文出现前有数秒推理等待。
- 当前 DE 在 `finished=True` 且没有正文时抛 `MODEL_RESPONSE_EMPTY`，并在错误分支之前未发出 usage/done，导致知君看不到该失败的结束原因及用量。

### 尚未确认

- 三个合成请求都返回了正文，没有复现 18:55 原请求的完全空正文。不能断言该历史请求一定是推理耗尽预算，也不能宣布线上问题已修复。
- 不排除特定请求/供应商响应形态不同；不从单次对照估算成功率或断言中转站始终可靠。
- 没有重放真实用户上下文，也没有执行桌面到模型的端到端回归。

## 使用

在装有对应 DE 运行环境的盒子容器内执行。路径必须明确指向目标工作区，不扫描其他工作区：

```sh
python diagnose_cloud_stream.py \
  --allow-network \
  --runtime-db /var/lib/zhijun/data/zhijun_models/<64位workspaceId>/runtime.db \
  --scenario short \
  --max-tokens 1024
```

也可通过 SSH + `docker exec -i ... python - ... < scripts/diagnose_cloud_stream.py` 从标准输入运行，无须安装或替换服务文件。`--de-backend` 默认 `/opt/mindos/app/backend`。

参数：

- `--allow-network` 必须显式传入；每次运行最多一个可能计费的请求，没有自动重试。
- `--scenario short|reflection` 仅允许两条内置合成问题，不接受任意提示词或真实材料。
- `--max-tokens 1024|4096` 仅对该次探针生效，不改生产设置。
- `--use-worker-budget` 从已部署 worker 加载纯预算策略；报告同时记录请求原预算、有效预算和策略文件 SHA-256。不会加载 worker 服务、读取其业务数据或伪造授权。
- 单次超时不超过 30 秒，总预算不超过 60 秒（若配置更短，使用较短值）。复用实际 DE 的 DNS 固定、TLS、目标限制和字节上限。

生产配置通过 SQLite 只读连接复制到私有临时目录；仅对临时副本初始化配置/密钥加载器，退出自动清理。缺密钥、工作区未启用 OpenAI 兼容通道、使用受管租约模型等情况停止，不回退到其他工作区或本地模型。配置或加密凭据变化时取消探针，不复用过时配置。

观测器包装当前 DE 的 `_lines()`，原样向生产解析实现交付响应行。它只保留固定白名单计数，原始帧仅在内存中短暂解析，不落盘。未知事件名、结束原因归一化，异常不输出原始文本。不得给此工具添加完整请求、响应、密钥、推理内容日志。

输出中的 `classification` 表示**在解析器停止之前观察到的响应形态**：`visible_delta` / `final_only` / `reasoning_only` / `empty`，不是语义完整性判断。纯空白增量也会记为 `visible_delta`；是否有完整有效答案仍需业务层判断。摘要中的 `final_chars` 是快照最大长度而非与增量累加。

## 验证及后续修复边界

离线测试，不需要网络或 DE 运行环境：

```sh
rtk proxy python3 -m unittest discover -s backend/tests -p test_cloud_stream_diagnostic.py -v
```

建议后续分工：

1. **知君**：按模型推理能力和任务类型设置合理的输出预算，并与正文长度要求分开；不要把 `effort=low` 当作禁用思考。所有请求参数变动必须发生在摘要、授权、请求摘要签名之前，不能在外发时偷偷扩充或自动重试。
2. **Data Engine / 供应商适配**：明确中转站支持的思考控制参数，保留不含正文/密钥的结束原因、是否出现推理、用量等诊断字段。当前仅支持正文增量，最终快照兼容需有真实响应证据和防重复测试后再改。
3. **联合验收**：普通对话、长回复、结构化检索规划分别验证；确认首段正文延迟、正常结束、长度截断的用户提示，以及无正文失败的诊断可追溯性。不要把推理内容冒充答案或自动切换本地模型。
