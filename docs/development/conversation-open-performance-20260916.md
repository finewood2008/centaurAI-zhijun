# 打开会话性能优化（2026-09-16）

## 目标与验收

- 已选会话正文的任务提交和结果读取优先于排队中的辅助读取；不提高请求配额、不占用心跳/取消保留额度。
- 会话页有明确会话 ID 时，不在启动阶段加载仅供空白页使用的本体统计。
- 只读会话权限检查不重复初始化附件表；保留账户/设备/工作区权限校验。
- 快速切换、取消、过期连接不能显示另一会话的数据；不新增持久正文缓存。
- 测试验证队列顺序、普通业务限流、前台标记来源与后端权限回归。

## 计划与影响范围

1. [x] 检查 ConversationPage、product session、business bridge、调度器和后端详情查询。
2. [x] 桌面 product-session 按已验证的操作定义标记正文读取；bridge 给予普通业务范围内较高优先级（含取结果）。
3. [x] ConversationPage 首屏统计按需加载；后端详情 scope guard 避免重复 ChatImportStore DDL。
4. [x] 补充行为测试，运行前端、桌面、后端回归与类型检查。
5. [x] 记录验证结果及发布要求。

依赖：不改 Data Engine 协议、SDK、授权与任务格式。后端独立修改委派审查过的子任务，主代理负责前端/桌面及集成。

## 已知证据与限制

- 桌面每次业务读取需要提交任务并取结果；普通任务在限流队列共享预算。
- 会话辅助请求已有分阶段加载，但后续切换仍可能与其排队竞争。
- GET detail 的出处查询已经批量化，不是逐消息 N+1。
- Data Engine 的任务持久化仍可能贡献额外耗时，此次不直接修改另一个团队的组件。
- 尚未取得用户设备端到端前后对照数据，不能承诺固定毫秒值。

## 验证结果

- 桌面全量：361 tests，360 pass，1 Windows-only skip，0 fail（Node 22.23.2）。
- 前端全量：237 tests 通过；类型检查通过。原始启动顺序断言同步为按需读取，新增真实页面函数测试，确认已有会话不加载 landing-only stats，空白页仍加载。
- 新增真实 loadConversation 函数竞态测试：A→B，先返回 B 再返回 A；A 被取消且不能覆盖正文、清除 B 加载状态或启动 A 的辅助读取；每个目标只请求一次。
- 后端详情/store/management API/compat/outcomes/worker：43 passed，5 subtests passed。覆盖 scope 404、Worker proof、Python 写锁不阻塞只读详情及出处/草稿/判断返回兼容。
- 限流集成基准：相同虚拟时钟、真实 product session→adapter→bridge→scheduler，普通突发额度用尽且有 3 个辅助提交排队；旧顺序详情完成于 3000ms，新顺序于 1200ms（减少60%）。这是排队基准，不是生产端到端耗时；网络与盒端执行时间未计入。
- 仍保留普通业务600ms令牌补充、滚动请求上限、心跳/取消保留额度、队列老化防饥饿；没有新增跨账号/设备正文缓存或推测性预加载。
