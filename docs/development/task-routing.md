# 本地与在线模型路由

## 用户可见行为

- 本地模型和在线模型是明确选择，不根据服务健康状态暗中切换。
- 在线服务配置成功不等于已经获得资料外发授权。
- 在线失败保留失败状态，由用户选择重试或改用本地；系统不自动降级。
- 系统生成的话头可以带一次性本地限制。用户在发送前显式选择在线后，以用户选择为准；一次性限制不能泄漏到后续消息或其他会话。
- 历史附件来源、当前检索片段和不使用材料的消息遵循同一模型选择语义；不表示正式 workspace 仍提供附件上传。

## 请求流程

1. 读取当前会话或新会话默认路由。
2. 根据本轮输入与获准历史判断是否检索材料；需要时组织独立 Query，调用 Data Agent Search，按敏感交付状态处理确认和暂扣，再由用户选择本轮采用的片段。普通结果也默认不选，不将未选内容送入模型。
3. 复核 Evidence Resolve，结合个人理解、章程和事项生成来源预览；另行检查在线服务、用途、来源版本和实际请求授权。缺失时让用户允许、忽略相关来源、改用本地或取消。敏感交付、材料选择和在线外发不能合并为一次授权。
4. 使用稳定请求标识提交消息。只有服务端持久化本轮后，才消费一次性话头状态。
5. 保存回复的 provider、model、external、来源和授权回执。

路由预览失效或配置修订变化时，可以在仍未收到流事件的前提下有界地重新预览；流已经开始、网络状态不明、用户取消或来源变化后不自动重播写请求。

正式 worker 与 Web 复用知君 `OpenAICompatibleProvider` / `OllamaProvider`，由知君执行实际本地/在线请求、来源授权和流式解析。工作区配置及云端凭据由知君独立保存，不继承 DE/Web 部署默认密钥。RAG 使用独立的 App REST 鉴权链；DE 不代理知君聊天和本体模型调用。Remote Agent 只承载连接与受控转发，不决定模型路由。Direct/Relay 是电脑连接盒子的路径，与本地/在线模型选择无关。完整链路见 [产品架构](architecture.md)；升级配置见 [工作区模型配置](../workspace-model-configuration.md)。

## 来源与授权

- 文件原件不会因为允许使用提取文字而自动外发。
- 画像、对话、章程、事项、成果和文件文字分别保留来源与版本。
- 撤回、删除、服务切换、workspace 变化或来源版本变化后，旧授权不能直接复用。
- 默认授权只覆盖用户明确选择的稳定范围；它不能跳过桌面安全通道或扩大到未来新增用途。
- 受限来源可以按用户保存的处理偏好在该轮改用本地，但这必须在界面与审计中可见。

## 如何确认实际模型

界面的模式选择表示会话路由状态，不足以证明某条已生成回复的实际执行通道；模型正文中的自称也不可信。请检查：

- 会话消息中的 `provider`、`model`、`external` 字段；
- 单条消息的 receipt；
- 盒端 routing audit。

在 NPU-only 部署中，本地 provider 的兼容协议名称也不能用于判断 CPU/NPU。例如 Ollama-compatible 只描述协议；实际是否通过 NPU adapter 和推理服务执行，由 CentaurOS 的端口映射、进程配置和运行审计决定。

NPU-only 约束本地模型推理，不要求桌面、Python 业务编排或数据库停止使用 CPU。检索、人工确认、模型排队、上游首 token、流传输及终态处理应分段定位；云端有调用记录不能证明最终回答已完整到达桌面。
