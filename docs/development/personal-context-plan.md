# 个人上下文：章程、本体与经历共同参与对话

2026-09-04 实施记录。

## 已落地

- `ContextPlan` 区分工作情境、轻量身份背景、相关证据和排除原因；权限依赖不是阅读回执。章程仍走统一的必需约定检查，不占用证据名额。
- 工作情境保存在本地会话消息元数据中，携带用户原话及来源；短回答、明确纠正与刷新可以续接，换题清理无关事件。助手提问不是用户已经承认的事实。不新增长期画像或自动修改章程。
- 身份背景最多 4 条／600 字；普通证据最多 8 项、补查后最多 12 项；待验证理解最多 1 项。相关性优先，贴合度不能隐藏低贴合的真实经历。
- 本体使用带实体别名、关系、情境、例外、时间的本地词法与嵌入检索。索引在本进程可重建，只加载已安装本地权重，禁止下载，失败时保留关键词检索。
- 历史用户原话、会话摘要、判断及结果、情境复盘和材料正文快照参与召回。设备／生命周期先过滤；分批扫描全量范围后取候选，不先截断到前几十条。一个文件最多两个不同正文窗口，保留准确位置且共用文件版本来源。
- 来源在读取时冻结版本；发送前重新核验。原话、摘要和派生理解按共同来源与内容去重；时间、层次与例外不能因裁剪而改变含义。
- 聊天、回复辅助、判断草稿／候选、情境复盘复用同一计划组装。普通聊天不增加模型调用；复杂请求最多一次结构化补查，使用当前在线主模型，规划只生成本地搜索条件。
- 补查缓存继承规划输入的所有来源限制；新发现必要但未授权资料时暂停最终回答，保存原消息与阶段。授权后使用相同请求标识续接，不重复规划、用户消息或回答；不静默切换服务。
- 界面分开“遵循的约定”“提供给模型的信息”“回答明确引用的信息”；只有实际处理后的回执才显示提供数量。引用 ID 必须存在于本轮实际提供集合，不能声称已经验证模型内部使用方式。

## 存储与权限

沿用现有本体、会话、资料和授权存储。新增 `context_lookup_stages` 是本地临时处理缓存，删除会话会清除对应缓存。旧数据不批量重写、确认或授权。

实施前通过 SQLite backup 备份 ontology、conversations、growth 数据库，文件标识 `pre-context-plan-20260904-230444`，完整性检查通过。

新的来源版本绑定了层次、主体、关系与时间等语义字段。旧来源版本无法核实时保持受保护状态，不把旧授权升级为新授权。不访问 claude.ai 或 anthropic.com。

## 使用方式

继续原对话即可；新回复下可展开依据。需要补查授权时，点击消息下的“核对补充资料并继续”，也可以明确选择仅本地处理。不要求重做初始化，不改变正式章程与已确认本体。

本机启动核对：8618 后端健康、5173 页面正常，当前对话已刷新并保留全部原消息。当前主模型为 Qwen，但用户的默认授权及默认跳过方案仍绑定此前 DeepSeek 服务，因此显示“检查设置”。这不是本次自动迁移的范围；用户需要核对新服务后才可让原来的默认处理方式适用于它，未代用户开启。

仍应持续用固定案例评价：条件遗漏、错误引用、重复追问与回答有用性，而不是提供条数增加。引用标识校验只保证来源对应，不保证每项推论都正确。
