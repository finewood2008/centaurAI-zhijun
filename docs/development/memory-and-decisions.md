# 记忆、章程与判断

## 信任层

知君区分三种长期状态：

- 对话记录：用户和助手的原始交流及其来源回执。
- 工作理解：系统提出但尚未由用户确认的候选，只能带不确定语气使用。
- 已确认理解：用户确认或修订后的内容，可以按单独授权进入其他用途。

用户可以确认、部分确认、限定情境、忽略、修订或撤回理解。系统推测、资料观察、用户原话和理想方向不能混为同一种事实；被纠正的内容保留审计并防止无依据回流。

## 低打扰整理

记忆整理默认只提出少量具有长期价值的候选。一次性活动细节、AI 辅助表达和空泛推测不应直接成为稳定人格理解。事件细节可以先合并到本地小结，只有用户主动保存后才成为有来源的情境记录。

记忆候选、校准和小结共享有限注意位，处理一项后不自动轮播下一项，也不抢输入焦点。用户选择“仅在我要求时整理”后，普通对话不自动排队新的理解任务；显式“请记住”仍需用户核对。

## 对话到本体的执行与恢复

主回复成功完成后，符合记忆策略的用户消息排入 `extract_turn`。当前提取以本轮用户原话和上一条助手的有限上下文为基础，不等同于全会话重新归纳；失败、中断的回复不会自动补抽，带材料的讨论也保留现有来源隔离规则。

短而完整的直接身份自述（如“我是程序员”“我是医生”）可进入模型提取，不因不足 6 字被跳过；这不是直接写入本体的规则，仍需经过模型、原话证据、长期价值和范围检查，候选仍为 `working`。问句、引述或不完整片段不获得这条短句豁免。

长期候选写入 `working`，在对话“待核对”和本体页展示，用户确认后才进入 `confirmed`。情境信息先合并为可选小结草稿；任务成功不代表必然产生长期候选，空结果、去重和价值筛选都可能不新增本体。

在线聊天授权与后台整理授权是两个独立用途。Web 与盒端 worker 均由知君来源授权、路由预览及 `EGRESS_PERMIT` 在实际 HTTP 边界检查；聊天与 `extract_turn` 复用知君模型适配器，不再索取 Data Engine 模型外发凭据。后台缺少当前用途授权时在模型调用前暂停，保留预览供客户端核对；不能把聊天许可自动扩大为本体整理许可。

客户端仅跟踪本次聊天新排入或用户明确恢复的整理任务。用户已明确开启且仍适用的默认来源授权可覆盖相应后台用途，任务直接执行，无需前端代签 DE 凭据；不适用时显示“等待核对”，核对后按 `jobId` 恢复。每个任务的自动恢复次数有限，不自动重放其他历史失败或暂停任务，也不静默切换模型。未携带 `jobId` 的人工恢复仍支持处理所选用途的历史积压。旧盒端返回 `deConsentRequired` 时前端保留兼容，不代表新 worker 仍走该链路。

排查“聊过但本体为空”时，依次检查：是否排入任务、任务暂停或失败原因、是否只有情境小结、是否有 `working` 候选。不要把“没有候选”统一解释为用户没有确认。整理完成或暂停后应同步刷新候选与“模型与授权”的待处理状态；状态请求失败不能当作任务已经完成。

部署验收必须核对目标盒实际运行的 `app.py`、`provider.py`、`jobs.py`、`routing.py` 等文件及完整源码清单，不能只看客户端版本或遗留兼容 `zhijun_worker/model.py` 的哈希。本地测试通过、另一台盒子升级成功或聊天有回复，都不能替代当前盒真实 `extract_turn` 产出候选的证据。2026-09-15 公司盒复查见 [现场记录](programmer-memory-20260915.md)。

验收重点：没有任何 DE 模型/授权能力调用也能完成本体抽取；缺少知君用途授权时无模型外发；核对后恢复可生成 `working` 待确认候选，不自动写成用户确认事实；配置变化使旧默认自动外发授权失效，来源变化使旧逐项授权失效；定向恢复不触碰其他消息，重复点击不重复入队。历史错误 `MODEL_EGRESS_CONSENT_REQUIRED` 需用户主动重新整理，不做数据库迁移式重放。

## 自我校准

校准用于用新经历检查旧理解，而不是训练第二个个人模型或给用户打分。事前观察与事后结果分开保存；保存对照不会自动改写本体，只有用户明确应用修订时才通过统一状态入口替代旧理解。

校准记录保留原理解、判断、证据和版本。不同情境、阶段、愿望和长期倾向必须分开处理，不能因为一次结果就推断终身原则。

## 人生章程与判断

人生章程由用户建立、编辑和发布，系统可以提出建议但不能自行改变。章程中的挑战方式、边界和静默领域影响模型行为，不等于资料外发授权。

判断流程把当时的选择、理由、把握和预期与之后的真实结果、复盘分开。判断草稿只接受有来源的内容，必须由用户确认后才写入判断簿；复盘经验可以形成候选理解，但不会自动晋升为原则。

## 来源与权限

- 保存理解、章程、判断或小结不自动授予在线模型使用权限。
- 任何派生内容都继承原会话、资料、判断或成果的来源限制。
- 删除、撤回、版本变化或来源链缺失后，旧授权失效或保守停止使用。
- Context Pack 和其他 Agent 只能读取用户明确允许带走、已确认且非受限的投影。
- 本地专用任务不会静默切换到在线；NPU-only 是否成立由 CentaurOS 运行时和审计确认。

## V3 统一回看：无需新增盒端接口

客户端 `/review` 聚合 `GET /api/mindos/growth/decisions` 和分页 `GET /api/mindos/conversations`。仅按 decisionId 或已有 evidenceRefs 的 conversationId 合并记录，不能按标题猜测关联。来源与回访在同一条经历下提供原对话链接；空会话不作为经历，归档会话可主动选入查看，仍沿用已有归档规则。默认队列只包含到期、已有结果或主动选入的经历，已完成复盘单列为“留下的经验”；未来及未约定时间的选择可从选择器或既有深链接打开。

`shared/revisit.ts` 负责资格、明确来源关联与暂放版本判断。选入和暂放存为仅含 ID、时间和状态版本的本机偏好，不缓存原话，也不占用置顶字段。桌面持久键使用 accountId/deviceId/workspaceId，连接 generation 只用于阻止旧组件迟到读写；浏览器开发模式按 origin 保存。切换账号或盒子不会读取另一主体的安排。存储失败须显式告知且不假装保存成功。

选择器分页加载历史；再次进入时按已选 ID 补取首屏之外的对话。普通经历使用既有对话详情展示原话节选，不把任意聊天摘要当作结果。页面退出和主体改变后丢弃迟到详情，详情失败清空旧原话并保留重试。

选择、结果和复盘仍分别使用既有 growth 写接口。主动回看使用现有对话页面：普通经历回到原会话；选择记录复用 `POST /conversations {mode: review, decisionId}`。预填问题不自动发送，不复制私有历史到新请求，不绕过盒端已有的来源授权。

`/reflections` 客户端 API、独立卡片和两项桌面 catalog 操作已退出当前产品流程。成功聊天不再排入独立 reflection 后台任务，记忆提醒回到原本的候选理解与校准流程。历史服务端 reflection 存储、来源核验和兼容代码保留，不删除既有数据库记录；这不是当前客户端依赖，也不要求目标盒子部署这些兼容代码。

纯前端改版可以在现有盒端运行。旧页面深链接重定向到 `/review`，保留 query 和 hash。界面按当前设备工作区加载；离开页面或切换主体后丢弃迟到结果。

验收包含：五个导航入口（**这一条对应旧壳。沉浸式壳没有导航，回看是「昔」抽屉；PRD V2 的 P0 把沉浸壳定为默认后，这条验收要改写**，见[产品定义](../product/PRODUCT.md)「界面」一节）、旧链接参数保留、断线时零业务请求、到期及结果筛选、普通对话不自动进入、历史分页后主动选入并重开、暂放及恢复、取消不写入、归档只读、存储和详情失败、选择结果复盘保存后重开、按明确来源去重、桌面及 800/390/320 宽度布局，以及请求全部属于已有 catalog 且没有 `/reflections`。合成数据写入与真实盒端只读验收分别报告，不把本机测试等同于真实模型观察质量。
