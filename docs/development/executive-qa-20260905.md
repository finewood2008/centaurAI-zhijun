# 知君全流程验收：普通高管从零建立个人本体

日期：2026-09-05

## 1. 测试目标

本轮以一名虚构的普通高管“林舟”为主角，从空白设备开始，验证他能否：

1. 完成第一次认识，并在不被强制补齐所有资料的情况下开始使用知君；
2. 通过日常对话、文件和主动补充建立有证据、可核对的个人本体；
3. 区分事实、当前状态、长期认同、愿望、情境行为和知君推测；
4. 亲自确认或修改记忆、自我贴合度和人生章程，避免系统替用户定义自己；
5. 在现实决策中，让知君结合当前事情、相关经历、本体和章程给出有边界的帮助；
6. 在“良师、益友、知己”三个角色上达到可验证的产品表现，而不是宣称已经完整复刻一个人。

合成角色的关键约束包括：制造业数字化负责人、预算 8 万元、团队 3 人、每周可投入 4 小时，希望先做两周单客户试点；一项工作经历是真实事实，但本人明确表示它不代表长期追求。

## 2. 通过标准

### 良师

- 能引用当前问题真正相关的事实和经历，给出符合预算、时间和团队约束的行动建议；
- 不让章程挤掉具体事实，不让无关的“核心原则”挤掉当前问题；
- 缺少关键资料时说明缺口，最多追问一个必要问题，不伪装成已经知道；
- 低贴合度的真实经历仍可用于事实回答，但不再被当作核心意愿。

### 益友

- 允许用户只说一部分、暂时不决定或先休息，不把每轮对话都变成任务清单；
- “帮我开个头”给出可选择、可编辑的用户视角回答，而不是把问题换一种说法再问一遍；
- 辅助表达不会自动成为已确认画像，也不会制造重复证据。

### 知己

- 能接住短回答、代词和跨轮语境，并调取相关身份、关系、经历、原则和愿望；
- 能区分“过去通常怎样”“现在处于什么状态”“希望以后怎样”；
- 对不确定内容明确说不确定，不声称看穿潜意识或完整复刻用户；
- 只有服务器确实完成写入时，才可以说“已经记住、更新或作废”。

## 3. 覆盖的完整流程

- 新用户第一次认识、跳过与恢复、引导话题进度、开始使用；
- 普通对话、深入讨论、判断对话、跨轮情境恢复、回复辅助；
- 记忆候选的提取门槛、待核对、确认、修改、拒绝、去重与提醒频率；
- 个人本体六个分区、来源证据、自我贴合度、时间情境、历史纠正；
- 人生章程的对话起草、单篇 Markdown 编辑、部分确认、版本及执行边界；
- 文件上传、解析、重试、空文件、正文快照、附件直接讨论与真实引用回执；
- 本地与在线模型路由、逐用途授权、默认选择、撤销、待处理任务恢复；
- 外部模型供应商、模型发现、空回复兼容与失败反馈；
- 对话搜索、重命名、置顶、归档、恢复和自动恢复；
- 首页、判断、资料回收站、来源生命周期、后台整理和服务重启恢复；
- 桌面及窄屏下的菜单、抽屉、输入框、判断草稿和来源说明；
- 设备隔离、版本冲突、幂等提交、派生来源链和 SQLite 连接生命周期。

## 4. 本轮修复的主要问题

### 个人模型与记忆

- 修复统一模型路由后，本体、关系、历史判断、资料片段和会话情境没有完整接回的问题；
- 增加会话级当前情境，短回答不再脱离上一轮问题单独检索；
- 调整记忆准入：短句、操作语、助手生成文本和一次性情绪不会频繁进入本体；明确、稳定且可复用的个人事实和愿望仍会进入待核对；
- 新理解始终先进入草稿，不自动确认、进入检索或提高自我贴合度；
- 修复来源重复、旧内容被替代后仍参与当前画像以及多设备数据串用风险；
- 对所有生成任务增加统一约束：模型不得把自然语言回应冒充为已经完成的正式记忆写入。

### 对话、章程与权限

- 修复章程在上下文中占据主导、相关本体与具体经历反而缺席的问题；
- 章程保持用户主动修改的稳定文档，日常聊天不会自动改写；
- 逐任务、逐来源检查在线权限，恢复因旧粗粒度会话锁定而滞留的任务；
- 默认授权不再反复弹窗，但文件、画像、章程及新增用途仍遵守版本和服务边界；
- 授权撤销、服务切换或内容版本变化后会重新核验，后台任务不能绕过。

### 文件与来源真实性

- 修复附件虽被模型读取，界面却显示“提供给模型 0 项／引用 0 项”的错误；
- 显式附件现在进入本轮上下文计划，使用独立材料引用编号，并展示实际文本范围、资料与版本；
- 原文件仍留在本地，只有获准且实际需要的片段进入在线请求；
- 文件上传成功、解析完成和可以讨论被明确区分，失败不再锁住输入框。

### 稳定性与界面

- 修复 onboarding 双击、会话切换竞态、编辑失败丢输入、菜单被裁切、判断草稿被遮挡及窄屏横向溢出；
- 修复对话归档、搜索、定位、恢复及旧链接兼容问题；
- 修复 SQLite 请求连接没有及时关闭的问题。旧后端进程曾累计 163 个核心数据库句柄；新版在连续 50 次真实只读请求后为 0；
- 修复 DeepSeek 兼容通道对部分响应格式处理后返回空文本的问题，并增加传输层回归用例。

## 5. 自动化与实际运行结果

- 后端隔离回归：137 个测试模块，2309 个测试；0 失败、0 错误，14 个按环境条件跳过；
- 前端回归：32 个独立测试模块全部通过，失败模块 0、失败断言 0；
- 前端生产构建：TypeScript 检查通过，Vite 完成 2049 个模块转换；
- 历史界面兼容回归：22 个模块、412 个测试通过，10 个既有条件跳过；
- 合成高管端到端：从零初始化、候选确认、贴合度校准、Markdown 章程、外部权限、事件与人格分离、重启恢复全部通过；
- 隔离浏览器验收：桌面与 390×844 窄屏完成 onboarding、回复辅助、四条记忆确认、章程发布、文件上传与带来源回答；无横向滚动；
- 实际在线模型合成验证：意图连续性、良师、益友、愿望、纠正和自我认识六类请求均返回非空；纠正场景不会再谎称已完成记忆写入；
- 真实应用：后端已用新版本重启，健康检查、索引、对话、本体和章程页面正常；前端开发服务保持运行。

前端构建仍有一个非阻断提示：`taskRouting.ts` 同时被静态和动态导入，因此不会被拆成独立代码块；这不影响功能或构建产物。

## 6. 数据与隐私保护

- 所有写入式端到端测试均使用一次性合成数据库和虚构人物，没有批量修改、确认或外发真实用户记录；
- 实际在线模型验证只使用合成内容及用户已配置的供应商，没有向禁止访问的站点发送请求；
- 生产数据库在测试前已分别备份本体、对话、成长和运行设置四个文件，并通过 SQLite 完整性检查；
- 设备范围、来源生命周期、文件版本、模型服务和用途在发送前及正式写入前再次核对；
- 本轮没有把旧资料批量授权，也没有替用户批量确认历史本体。

## 7. 仍需长期验证的边界

本轮已经修复覆盖范围内全部可稳定复现的阻断问题，但软件无法通过一次回归证明“今后没有任何 bug”。以下项目需要真实环境或持续观察：

- 不同扫描件、图片和音频设备上的 OCR／转写质量；
- 每一家在线供应商、每一种模型和异常账户状态；
- 长时间弱网、额度耗尽、日级后台任务和超大资料库压力；
- 两台真实设备同时修改同一内容时的用户体验；
- 一个真实高管数周或数月使用后，知君是否确实更像合适的良师、益友与知己。

因此，产品成功不应以“本体点数更多”或“平均贴合度更高”衡量，而应持续观察：相关信息命中率、错误引用率、重复追问率、用户纠正成本、建议是否符合现实约束，以及模型能否根据真实结果修正理解。
