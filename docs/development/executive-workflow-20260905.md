# 知君：从理解用户到持续推进事情

2026-09-05，持续事项与文稿版本。未改写真实用户的本体、章程或旧对话；GitHub 发布以本版对应的提交记录为准。

## 本版可用的流程

1. 首页「正在推进」回到同一件事；无记录时可从「聊一件新事情」开始，文字只填入输入框。
2. 对话标题旁「事情与成果」打开抽屉，主动创建或关联事项。名称必填，目标、背景、下一步、实际结果允许逐步补充。
3. 沟通提纲、决策备忘录、会前准备、行动小结的入口只追加对话请求，保留已有输入，由用户发送。普通聊天不必使用这些入口。
4. 完整回复下「留下文稿」保存服务端原消息全文，保留消息及来源引用；用户可编辑完整 Markdown、预览、复制、下载。首尾空白、缩进、硬换行原样保留。
5. 记录实际结果后可主动「一起回顾这件事」。已暂停或完成事项不进入普通聊天，仅在明确回顾该事项时按原权限使用。换题后持续暂停参考，主动恢复或重新关联才恢复。

事项、成果、结果是可核对的工作记录，不是新的画像系统。它们不会自动确认个人理解、提高贴合度、修改章程、派发任务或发出提醒。

## 阅读与稳定性

- 本体增加直接展示既有原文的概览：身份角色、具体事情、原则、方向、待核对理解和近期记录。未设过视图偏好时默认概览；已有地图／列表偏好保留。
- 聊天正文提高可读字号，回复可复制；「整理成判断」「展开分析」解释操作目的。允许生成完整结构化文稿，不让普通闲聊字数约定约束完整成果。
- 章程保留法典式 Markdown 阅读、编辑、确认和历史，减少重复标题与装饰信息。资料检索入口更易找到。
- 首页来信卡片的内部网格可收缩，来源可换行，正文与继续按钮不越界。
- 连接故障只显示一个全局提示，不刷新页面或自动重发。后台整理失败可见并可显式重试，执行前仍检查权限和章程。
- `bash zhijun.sh start|status|stop` 统一开发入口；复用可核对的现有健康服务，仅管理自己启动的进程。不是开机启动服务，也不会自动循环重启崩溃进程。

## 数据与权限

- 新表沿用本体数据库，按设备隔离；乐观修订、幂等请求、审计版本和消息来源关联均在后端验证。
- 创建和编辑由用户明确操作；后台不能覆盖手工文稿。并发冲突不默默覆盖；明确放弃编辑后才载入最新版。
- 事项、成果采用新的来源类型，旧的默认授权不自动涵盖。复制为派生内容或手工编辑不解除原来源限制。
- 不允许用未授权的事项文本扩展在线检索；来源版本变化、撤销、删除、跨设备及多跳派生仍在统一路由检查。
- 上线前已运行数据库备份及哈希／隔离恢复验证。备份在本机 `backups/mindos-data-20260905-150948`，已加入 Git 忽略，不能提交私密资料。

## 仍需验证的部分

全量测试直接放在同一个 pytest 进程中会被已有模块级配置／单例污染，曾出现大量 403 误失败。本版增加独立进程执行入口，没有通过关闭生产写保护让测试通过；测试之间的全局状态清理尚未全面重构。

合成回归验证的是功能、边界和数据流，不代表已经证明实际在线模型建议的质量或长期「知己、益友、良师」效果。下一阶段应在用户明确授权下，用同一个模型比较真实管理案例的条件遗漏、错误引用、反复追问、成果可用性及后续实际结果。本版没有自动创建管理者画像、批量评分、扩大授权，也没有新增在线供应商或操作系统常驻任务。
