# 对话式人生章程与轻量初始化

2026-09-04。本次更新沿用 GrowthStore 的正式章程与不可变版本；未创建第二套本体，未批量确认真实记录。

## 体验

- 第一次认识围绕当前处境、眼下在意、发展方向、协作方式、边界五个可跳过话题；不再按七条用户消息锁定完成。
- 对话末尾的“第一次认识小结”打开抽屉，本体理解与章程分开确认；“先使用，稍后核对”不会发布任何记录。
- 章程可以只保存一项，空白为待完善，不代表没有限制。未选内容保留，用户可选择已有条目进行替换，也可以新增。
- 未建立章程时，“聊聊我的方向”创建普通对话并填入话头，不自动发送；确认后以主动修改和版本查看为主。
- 首份章程确认前，后台整理低于交互优先级，沿用本轮本地选择；缺授权暂停，由既有路由授权入口处理。确认后不再自动整理。

### 稳定章程（2026-09-04 后续调整）

- 首次确认形成正式章程后，不再从日常消息触发后台章程整理或更新建议；新情绪、经历、本体理解不改动章程。
- 已排队任务执行前重新检查，已有正式章程即停止；生成期间用户确认也会阻止新草稿写入。旧授权待办不再展示或恢复，审计记录仍保留。
- 普通对话不再显示遗留章程提议。未选中的初稿保留，可在用户主动编辑时查看，不主动追问。
- 页面主入口改为“修改人生章程”，手动编辑为主；“通过对话修改”只在用户主动点击后协助起草，仍须明确保存才生效。首次未建立时继续提供“聊聊我的方向”。
- 后续版本只来自用户主动修改与确认，不批量改写已有章程或删除历史版本。

### 入口归属（我的本体）

- 人生章程已迁至 `/mindos/me/charter`；“我的本体”标题下通过“本体理解 / 人生章程”切换。章程独立于圆圈图谱和贴合度，不增加一级侧栏项目。
- 判断页移除章程管理表单与加载；实际绑定的版本通过“参考人生章程第 X 版”链接至只读历史视图。对话出处同样跳转到使用时的版本，不用最新版替代旧依据。
- 首次对话整理、部分保存、主动修改及版本库复用原有接口和存储。本次仅迁移前端入口，没有数据库迁移或记录重写。

## 接口与数据

- `GET /api/mindos/conversations/{id}/charter`：作用域内的草稿、当前章程、话题进度、暂停/失败状态。
- `POST .../charter/suggest`：`requestId / previewOnly / routeRevision / localOnly`，统一 `charter_draft` 用途；独立于聊天生成锁。
- `POST .../charter/{draftId}/review`：`revision / selections / replacements / skip / requestId`。版本比较、发布与草稿状态更新在同一个 growth.db 事务内。
- 既有 `/api/mindos/growth/charter` 支持部分字段，以及可选 `expectedVersion / requestId`。新前端始终使用这两个保护字段；旧请求仍兼容。
- growth.db 增量加入章程 `metadata_json`、`charter_drafts`、`charter_draft_actions` 和 `charter_writes`。元数据区分字段状态、引用和是否修改，不改变旧版本。
- 新的待确认项汇集到同一批次；相同来源的已跳过/已接受提议不因重复总结再出现。正式版本改变后，旧草稿不能直接覆盖，需要重新整理。
- 话题进度根据原始消息、明确跳过及服务端记录的当前话题做本地登记，附消息 ID。这是“已聊过”，不是 AI 对用户意图或人格的判断。

## 权限边界

- 整理只输入有界的用户消息，不输入原文件、整个资料库或模型总结；引用必须逐字存在于对应消息。
- 选择“不携带受保护旧历史”后，在线章程整理同样遵守该上下文起点；没有新消息时不会调用模型。仅本地处理可继续读取本地旧记录。
- 草稿继承模型实际使用的全部上下文来源，不能仅保留最终引用的那一句。编辑和确认不解除原始来源限制。
- 统一来源解析增加 `charter`（按版本和字段）与 `charter_draft`。新版本使用新的授权键；历史判断仍保留旧版引用。文件授权独立有效。
- 当前路由仅选择相关章程字段；协作方式和决策边界优先检查，愿望不当成已实现的事实。实际使用版本写入回答出处。
- 旧未路由的外部请求不自动携带章程。没有向 USER.md 或通用上下文包添加章程字段。
- 默认授权的用途快照不会被升级代码扩大；章程来源仍需明确授权。禁止访问域名的检查保持不变。
