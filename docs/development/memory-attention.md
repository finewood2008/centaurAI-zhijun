# 低打扰记忆整理

## 行为

- 偏好 → 对话中的记忆整理：默认“仅重要内容提醒”，可改为“仅在我要求时整理”。设置按设备持久化，不改变在线授权、既有本体或资料导入设置。
- 新对话抽取先校验原话，再判断长期用途。每轮最多一条长期候选；置信度不是长期价值。单轮推测、空泛理由不准入。AI 辅助表达和一次性活动细节不作为稳定人格依据。
- 临时计划、事件细节合并到同话题的一份本地小结，不立即写入 Claim。小结入口在对话工具区，按需打开抽屉。保存前显示实际的 120 字以内事件记录及完整引用；用户主动保存后仅为 context_only，愿望保持 aspirational，自我贴合度不变。
- 同话题只有一个持久化核对位，记忆和贴合度校准共用。处理一张后不轮播下一张；刷新不重置预算。其余重要候选仍能从本体待核对入口查看。
- 话题边界采用保守规则：同一会话持续为一个话题，明确“换个话题／另外一件事”等另起话题；明确请求“请记住……”单独提供核对机会。不增加意图分类模型调用。
- “不用记住”撤下本次新生成的 working 候选，审计注明这不是否认原话；不会修改已确认记录。普通复述不会再产生相同候选。已保存或放下的小结不会随补充自动重新打开。
- 仅在我要求时整理：不自动排队抽取和贴合度提议；明确记忆请求仍需确认。执行任务前、模型返回落库前再次检查偏好。明确“不要记住”在模型调用前拦截。

## 存储与边界

`memory_policy / memory_admissions / memory_attention / memory_drafts` 是本体现有数据库上的增量表，不迁移或批量改写旧 Claim，不添加授权。小结只保留事件起点及最近更新（最多 8 个片段）；不是第二套个人模型，不自动进入通用上下文包或 USER.md。

小结保存的证据保留原消息、实际 routingSources 和 AI 辅助来源。外发继续由统一路由逐次核验来源、版本、服务、用途；保存事件不意味着授权。删除对话清理这几张表的会话数据，已确认事件按原规则保留。

策略修改和小结保存采用版本检查；重复提交幂等。候选展示必须匹配当前会话原用户消息之后的助手回复，禁止全局 inbox 降级与“挂到最后一条”的兜底，也不自动滚动或抢输入焦点。
