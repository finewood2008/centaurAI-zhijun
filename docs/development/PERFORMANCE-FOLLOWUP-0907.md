基线：桌面 `eebd58b`，公司盒 DE `9fdff00`。用户反馈仍慢，不能用上一轮请求批次改善替代本轮验收。

- [ ] 主 agent：检查导航守卫、对话首屏请求顺序；减少已完成引导用户的重复导航请求。仅缓存当前桌面连接中的 ready 导航状态，最多 30 秒；切盒、断线、退出、引导更新必须失效。业务鉴权与页面业务数据始终走原通道。
- [ ] 主 agent：对话列表优先于非关键统计请求发出；保留请求取消、序列检查和错误展示。
- [ ] DE agent：仅修改 `backend/mindos/zhijun_gateway/manager.py` 与独立测试，持久结果变更后唤醒 poll；保留最长 100 ms 的授权复验周期、现有 owner/TTL/持久化行为与外部协议。
- [ ] 图标 agent：只负责 shell 图标资产、构建脚本、图标测试；保留半人马图形，补齐圆角底板、真实透明外缘和留白。图片工具无法输出 alpha，替代处理等待用户明确答复。
- [ ] 主 agent：集成审核、针对性回归、桌面构建、公司盒与实际 Dock 验证、文档与远程提交。任何部署须使用独立版本目录并保留当前运行版本回退。
- [ ] SDK agent：在独立 OS worktree 中只修改 sidecar 的 `main.go` 与同目录测试；原生 request 最多 8 项并发，控制关闭不被饱和请求堵塞，按原 request_id 输出完整响应，断管/退出有界清理。主 agent 审核响应内存上界、构建并固定新产物哈希后，再做真实 Direct 验证。

依赖与边界：桌面仍通过主进程 → Consumer SDK → Agent → DE 的受控 HTTP 通道。当前每项业务读取采用 start/poll 两步，不擅改签名路由或响应合同。磁盘全库扫描成本另有证据，尚未纳入本次最小补丁。

验证须覆盖：ready 缓存期限、未完成/错误不缓存、并行请求合并、过期响应不跨连接回填、引导更新失效；poll 通知竞态、并行读取、取消/吊销、SSE 首块；PNG 外缘真实 alpha 与实际 Dock 显示。记录合成基准和真机观测的不同范围，不宣称未测的端到端耗时。
