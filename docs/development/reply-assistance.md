# 低压力回复辅助（2026-09-04）

## 体验

- 普通对话、首次认识、回访共用最新完整回复下的一行入口：「换个说法」「先放一放」「帮我开个头」。前两项只填入请求；第三项由用户主动触发一次模型生成。不会自动发消息或每轮预生成。
- 候选为 2–3 句、每句不超过 60 字；允许没有合适候选，固定保留自己说、换一组、收起。模型被要求澄清而非猜测经历、内心或唯一答案。
- 选择追加到已有输入后，可修改、撤销，再由用户发送。撤销仅移除仍原样存在的插入片段，不删除用户随后所写；若插入片段已被修改，提示手动调整以保留编辑。
- 草稿及辅助来源按会话保存在本机浏览器会话存储，刷新可恢复。候选批次保存在本地数据库，刷新只读缓存，不再调用模型。窄屏候选随正文滚动，输入框独立常驻，展开不抢焦点、不自动滚动。
- 对话操作不抽取个人事实，也不计作首次认识问题的回答。普通回复默认先简短回应，每轮最多一个具体问题，允许部分回答或暂不确定。

## 存储与接口

- `conversations.db` 增量增加 `reply_assist_batches`，关联会话且请求标识唯一；删除会话级联删除候选，不影响资料库。没有批量改写历史消息或画像。
- `GET /api/mindos/conversations/{id}/reply-assistance` 返回仍有效的最新批次或 null。
- `POST` 同地址：`messageId`、`requestId`，可选 `previousBatchId`、`previewOnly`、`routeRevision`、`localOnly`。绑定最新完整助手消息、上下文与处理模式修订；重复请求复用结果。生成前后都检查上下文，生成不占聊天锁。
- 发送及路由预览新增可选 `replyAssistance: {messageId, selections: [{batchId, candidateId}], control?}`。文件批次发送同样支持。服务端验证所属会话、设备、版本及来源，不接受客户端伪造来源清单。
- 正式用户消息保存 `meta.replyAssistance`（来源、是否修改、候选引用、稳定证据键）及 `routingSources`。仅浏览/点选/填入候选不写消息、不写本体。重试沿用原消息元数据和请求标识。

## 权限与画像

- 使用统一任务路由，新增独立 `reply_assistance` 用途。已有默认授权冻结的旧用途集合不会自动扩张；现有授权界面显示实际拟发送上下文。不会自行启用在线、修改默认同意或切换服务。
- 候选及其编辑后表达保留完整来源链；`omitSources` 不能移除已派生进用户输入的来源。实际模型调用前及生成完成后重新检查模式、服务、生命周期、版本与授权。文件授权和画像授权仍分别有效。
- 辅助表达可以产生待确认理解，但不能自动确认、晋升或为旧理解追加重复证据；不得作为自动自我贴合度提议的独立证据。对话、判断候选、摘要对来源作明确标注；派生历史和后台任务继续使用同一外发检查。
- 文本编辑不会清除辅助来源。清空输入才清除来源；来源失效时保留草稿，提示重新生成。手工复制到其他应用再粘贴无法可靠自动识别；本功能不宣称能追踪跨应用剪贴板。

## 验证与发布

新增后端测试覆盖去重、并发/上下文变化、跨设备与删除、控制消息、辅助理解待确认、附件元数据、重试、用途变化、来源版本、撤销授权、实际 HTTP 边界及历史/摘要/后台派生。前端测试覆盖追加、修改、撤销、长度与旧问题来源。

浏览器使用独立临时数据库、合成对话和模拟模型检查生成—填入—编辑—撤销—手动发送、刷新恢复及 390px 窄屏；没有用真实用户资料调用模型。这些检查验证交互与权限机制，不保证模型生成内容始终无偏或无事实错误。

发布前分别对本体、会话及成长数据库执行 SQLite 在线备份并校验完整性；备份文件位于 `data/db/*.pre-reply-assistance-*.db`。恢复旧库会丢失其后的新消息，因此回滚先另行备份当前状态，不直接覆盖真实数据。

本次上线前最终备份时间为 `20260904-170417`，三个备份完整性均为 `ok`；当时有 18 段会话、132 条消息。最终相关后端回归 303 项及 25 个子测试通过，含 20 项回复辅助测试；前端构建、回复辅助与既有交互契约测试通过。两个旧模型解析测试补齐模拟路由许可，并新增无许可不得到达 HTTP 的检查，未放松生产权限逻辑。

## 回答口吻修正（同日）

用户反馈候选在替知君追问。原请求末尾是 assistant 消息，提示又只说「回复起点」，容易继续助手角色。现在把对话序列封装成带说话人标签的参考数据，用最后一条 user 任务明确要求起草用户可直接发送的下一句回答；候选提供不同的立场、程度或保留，不再给话题目录或待填框架。

- 拦截明显助手口吻、问句和部分空泛话头；移除自动把最后一个候选替换成通用「还没想清楚」的逻辑。模型可保留与当前问题相关的不确定选项，不能替用户确认事实或画像。
- 新批次保存 `formatVersion: 2`。旧批次不再作为最新候选显示，也不自动重新生成；原批次和已填入/已发送内容的来源链保留，不篡改审计、权限或历史数据。
- 展开提示为「你可以这样回答」，仍然选择后填入、修改后手动发送。
- 相关回归 136 项及 16 个子测试通过，前端构建与追加/撤销测试通过。`scripts/reply_assistance_smoke.py` 使用独立临时库与固定虚构案例测试实际模型；在线 4 组结果均为用户回答并通过格式检查，本地测试仍有问句被校验拒绝。格式检查不能保证观点无偏或所有细节都有依据，用户选择与画像确认保持分开。
- 测试结果在 `data/diagnostics/task-routing/reply-assistance-*-v2.json`，未读取真实会话、画像或原文件。上线前再次备份三库至 `*.pre-reply-answer-fix-20260904-172313.db`，完整性均为 `ok`。
